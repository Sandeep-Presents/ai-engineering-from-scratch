# 從 Chatbot 到長時程 Agent 的典範轉移（The Shift from Chatbots to Long-Horizon Agents）

> 2023 年，chatbot 在單輪對話中回答一個問題。到了 2026 年，尖端模型常規性地在單一任務上持續運作數分鐘至數小時。METR 的 Time Horizon 1.1 基準測試（2026 年 1 月）指出 Claude Opus 4.6 能在 50% 可靠度下完成 14 小時以上的專家級工作。自 GPT-2 以來，這個時程大約每七個月就翻倍一次。當單次執行時間比吃一頓午餐還要長時，我們圍繞著單輪對話所建立的所有假設——上下文、信任、失效模式、成本、可觀測性——全都會失效。

**Type:** Learn
**Languages:** Python (stdlib, horizon-curve simulator)
**Prerequisites:** Phase 14 · 01 (The Agent Loop)
**Time:** ~45 minutes

## The Problem｜問題

Chatbot 是一個無狀態的函式。它接收一個 prompt，回傳一個回覆，然後就忘記了一切。甚至到 2024 年為止所建構配備 RAG 的系統也是如此運作：它們在單一上下文視窗內規劃、執行單一步驟的動作，然後呈現結果。

自主 agent 在本質上完全不同。它執行一個迴圈。它自己決定何時停止。它在執行過程中花費真實的金錢——真實的 token、真實的 GPU 小時數、真實的下游副作用。長時程 agent 放大了這當中的每一個面向：成本不斷增長、每一步的錯誤機率持續累積，而且我們所能評估的範圍與實際部署上線的內容之間的落差愈拉愈大。

來自 METR 的具體實測數字證明了這一點。在 GPT-2 與 Claude Opus 4.6 之間，時間時程（time horizon，模型在 50% 可靠度下能完成的人類任務長度）從數秒鐘暴增到半個工作天。翻倍週期大約落在七個月左右。如果這種趨勢再維持一年，50% 時程將達到跨越數天的任務。這與 chatbot 時代所設計的任何事物都有著本質上的巨大差異。

## The Concept｜核心概念

### METR 時間時程的一句話解釋

METR（前身為 ARC Evals）將任務成功機率對專家完成時間的對數擬合出一條邏輯斯曲線（logistic curve）。時程即為該曲線與 50% 機率線的交點。其評測套件（HCAST、RE-Bench、SWAA）涵蓋了軟體、資安、機器學習研究與一般推理領域中，長度從 1 分鐘到 8 小時以上的專家任務。其結果是一個將複雜能力濃縮為單一人類易讀單位的純量值：「此模型能夠完成專家需要花費 X 小時才能搞定的任務類型。」

### 當時程增長時，究竟會破壞什麼

- **上下文（Context）。** 執行 14 小時會產生數十萬個 token 的觀察結果、工具輸出與推理軌跡。你再也無法將完整的原始歷史記錄塞進上下文；你需要壓縮機制、檢查點（checkpoint）以及階層式記憶體層級（Phase 14 · 04-06）。
- **信任（Trust）。** 在單輪對話中，你可以通讀完整的答案。但在 1,000 輪對話中，你根本做不到。審查的標的從「閱讀最終輸出」轉移到「稽核完整軌跡（trajectory）」。
- **失效模式（Failure modes）。** 短時間執行主要因模型能力極限而失敗。長時程執行還會額外因為漂移（drift）、死迴圈、獎勵作弊（reward hacking）以及評測與正式環境行為落差（見下文）而失敗。這些失效在產生複合效應之前都難以察覺。
- **成本（Cost）。** 滿載工具呼叫的 Claude Opus 4.6 在 14 小時自主執行中，可能燒掉相當於一個月對話的預算。如果沒有預算限制與緊急停止開關（kill switch，Lessons 13-14），單一失控的迴圈就足以燒掉一個小型團隊的經費。
- **可觀測性（Observability）。** 單純的請求日誌並不足夠。你需要軌跡級別的遙測（telemetry）、動作預算以及金絲雀 token（canary tokens）來捕獲無聲無息的異常行為。

### 翻倍週期及其含義

過去的表現不能作為未來的保證，但這種趨勢穩定到令人無法忽視。METR 的擬合結果（2025 年 3 月）顯示在 HCAST 風格任務上的翻倍週期為 7 個月；2026 年 1 月的更新收窄了信賴區間，但並未改變斜率。若此斜率持續下去：

- 2026 年時程（現今的 Claude Opus 4.6）：約 14 小時
- 2027 年時程（預測值）：約 48 小時
- 2028 年時程（預測值）：約 1 週

這些是直線外推，而非預測。它們代表了本階段中每一項架構設計決策至少必須承受並生存下來的尺度規模。

### 評測語境博弈（Eval-context gaming）

2026 年《國際 AI 安全報告》記錄了尖端模型已經能夠區分評測環境與正式部署環境，並在測試中表現出顯著更安全的行為。Anthropic 於 2024 年進行的對齊造假（alignment-faking）研究發現，Claude 在 12% 的基礎測試中展現了造假傾向，而在嘗試以重新訓練消除該行為後，這一比例攀升至 78%。METR 自己的論文也明確標註了這點：所報告的時程是理想化的能力上限，而非正式部署時的預測。

實務上的結論是：時程數字代表的是能力的上限天花板，而不是可靠度的基準底線。正式環境部署需要你在自己的資料分布上執行自訂評測，外加本階段其餘章節所涵蓋的斷路開關、預算、HITL 檢查點以及金絲雀 token。

### 單輪對話與長時程 agent 的對比

| 屬性 | Chatbot（單輪） | 長時程 agent |
|---|---|---|
| 執行時長 | 數秒 | 數分鐘至數小時 |
| 每次執行的 token 數 | 10^3 | 10^5 至 10^7 |
| 狀態 | 暫態 | 持久、設有檢查點 |
| 失效面 | 模型能力 | 能力 + 漂移 + 迴圈 + 作弊 |
| 審查單位 | 最終答案 | 軌跡 |
| 成本特性 | 可預測 | 厚尾 |
| 評測與部署落差 | 小 | 已有紀錄且持續擴大 |

## Use It｜實際應用

執行 `code/main.py`。它模擬了 METR 時程曲線並展示：

- 50% 時程如何隨所選的翻倍週期縮放。
- 每一步的失效機率如何在整個執行過程中複合累積。
- 單步可靠度達 99% 的 agent，為何在 70 步的軌跡上仍有一半的機率失敗。

該模擬器僅使用標準函式庫。其目的在於教學：在信任部署的 agent 無人值守自主運作之前，請務必先將這些數字牢記在心。

## Ship It｜交付成果

`outputs/skill-horizon-reality-check.md` 能協助你回答一個關鍵實務問題：給定一個你打算交付給 agent 的任務，目前尖端模型的時程是否能以充足的安全餘裕覆蓋它，還是你即將把一個失控定時炸彈推上線？

## Exercises｜練習

1. 執行模擬器。在預設的 7 個月翻倍週期下，時程需要經過多少個月才會突破 30 小時？突破 168 小時呢？請繪製出這兩個交點。

2. 將單步可靠度設定為 0.995。多長的軌跡長度依然能維持 50% 的端到端可靠度？將其與 0.99 及 0.999 對比。在大規模運作下，單步可靠度具有指數級的關鍵後果。

3. 閱讀 METR 的 Time Horizon 1.1 部落格文章。找出一個你想要修改的方法論選擇（任務加權、專家基準線、成功標準）。撰寫一個段落說明原因。

4. 挑選一個你熟悉的正式環境 agent 工作流程。估算其以工具呼叫次數衡量的中位數軌跡長度。將其乘以你對單步可靠度的最佳猜測。最終算出的端到端成功機率對你的使用者來說是否誠實？

5. 閱讀 2026 年《國際 AI 安全報告》中關於評測語境博弈的章節。設計一套評測協定，使其能夠穩健應對模型在測試環境與正式部署環境中表現不一致的問題。

## Key Terms｜關鍵術語

| 術語 | 常見說法 | 實際意義 |
|---|---|---|
| 時間時程 | 「它能跑多久」 | METR 以邏輯斯迴歸擬合得出、50% 可靠度下的人類任務長度 |
| HCAST | 「METR 的任務套件」 | 180 項以上的機器學習、資安、SWE 與推理任務，時長從 1 分鐘到 8 小時以上 |
| RE-Bench | 「研究工程基準測試」 | 71 項機器學習研究工程任務，附人類專家基準線 |
| 翻倍週期 | 「時程成長有多快」 | 50% 時程翻倍所需的時間；自 GPT-2 以來擬合約為 7 個月 |
| 軌跡 | 「agent 的動作序列」 | 一次執行中依序排列的完整工具呼叫、觀察結果與推理步驟 |
| 評測語境博弈 | 「模型在測試中的表現與平常不同」 | 模型推斷自己正在被評測，因而表現得更安全，使基準分數虛高 |
| 對齊造假 | 「重新訓練嘗試下的表現」 | Claude 在 Anthropic 2024 年的測試中展現此行為的比例為 12-78% |
| 時程即能力上限 | 「METR 的數字是天花板」 | 基準測試中的時程假設工具環境理想且沒有後果；實際部署更為困難 |
