# 混合記憶體：向量 + 圖譜 + 鍵值

> 混合記憶體並行維護三大實體儲存庫——利用向量處理語意相似度、利用鍵值（KV）實現毫秒級事實精確查表、利用知識圖譜處理實體關聯推論——並在檢索時透過融合評分層將結果無縫綜合併合。這是正式環境中極為普及的外部記憶體設計模式；Mem0（Chhikara 等人，2025）正是其最具代表性的權威實作。

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 07 (MemGPT), Phase 14 · 08 (Letta Blocks)
**Time:** ~75 minutes

## Learning Objectives｜學習目標

- 深入闡明為何單一儲存架構（純向量、純圖譜或純鍵值）在面對複雜的 agent 記憶體需求時本質上是不充分的。
- 指出 Mem0 所並行維護的三大實體儲存庫及其各自的最佳化目標。
- 描述 Mem0 的融合評分機制——相關性（Relevance）、重要性（Importance）與時效新鮮度（Recency）——並解釋為何它是加權總和而非階層過濾。
- 以純 Python 標準函式庫實作極簡的三合一記憶體系統，包含同步寫入三庫的 `add()` 與融合檢索的 `search()`。

## The Problem｜問題

任何單一儲存技術在面對以下三類典型查詢時，必然存在兩大軟肋：

- **語意相似度檢索**：「我們上週討論了關於 agent 漂移的哪些內容？」——向量檢索具備壓倒性優勢；鍵值與圖譜則徹底遺漏。
- **精確事實查表**：「使用者的電話號碼是多少？」——鍵值查詢勝出；向量檢索耗費運算，圖譜則顯得殺雞用牛刀。
- **實體關聯推論**：「哪些企業客戶共享完全相同的計費實體？」——知識圖譜能輕鬆遍歷多跳關聯；向量與鍵值則無能為力。

生產級 agent 往往在單一對話階段作業中同時發起這三種查詢。單一架構的記憶庫註定在其中兩種場景下給出糟糕的表現。Mem0 的核心突破在於：將這三種技術統一封裝於單一 `add` / `search` 介面背後，並透過數學評分函數將多維度結果平滑融合。

## The Concept｜核心概念

### 三大儲存庫並行運作

Mem0（arXiv:2504.19413，2025 年 4 月）在執行 `add(text, user_id, metadata)` 寫入時：

1. 透過大模型自輸入文字中提煉出候選事實三元組；
2. 將每個事實寫入向量儲存庫（生成 embedding）供語意語境搜尋；
3. 將每個事實以 (user_id, fact_type, entity) 為鍵寫入鍵值儲存庫，支援 O(1) 快速查表；
4. 將每個事實作為強型別邊（Edges）寫入圖譜儲存庫（Mem0g），支援多跳關聯推理。

在執行 `search(query, user_id)` 檢索時：

1. 向量儲存庫依餘弦相似度回傳 Top-k 最相關結果；
2. 鍵值儲存庫依查詢提煉的 (user_id, type, entity) 鍵直接命中精確記錄；
3. 圖譜儲存庫遍歷查詢實體所能觸及的子圖節點；
4. 融合評分層綜合計算三方結果並輸出統一排序。

### 融合評分機制（Fusion Scoring）

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相關性（Relevance）**：向量餘弦相似度、鍵值精確命中權重、圖譜路徑長度權重。
- **重要性（Importance）**：寫入時標註或自動學習得出（部分事實天然具備更高重要性：姓名、身分證字號、法規紅線）。
- **時效新鮮度（Recency）**：隨最後寫入或讀取時間呈指數衰減。

權重依具體業務產品進行調校：對話型聊天 agent 提高 `w_recency` 權重；法規審計 agent 提高 `w_importance` 權重；知識庫檢索 agent 則大幅提高 `w_relevance` 權重。

### Mem0g 與時態因果推理

Mem0g 引入了動態衝突偵測器。當新事實與圖譜中現有的邊產生矛盾時，既有的舊邊會被標記為無效，但**絕不予以物理刪除**。時態查詢（「該使用者在 3 月份居住於哪個城市？」）能透過遍歷歷史上特定時間點的有效子圖順利給出精確答案。

這正是 Letta 記憶淘汰範式在企業合規維度上的深化實踐。

### 基準實測指標

Mem0 官方論文公佈的 2025 年實測表現：

- **LoCoMo**（長篇對話記憶基準）：91.6 分
- **LongMemEval**（長路徑情節記憶基準）：93.4 分
- **BEAM 1M**（百萬 Token 極限記憶基準）：64.1 分

作為對照的基準線（128k 全脈絡 LLM、扁平純向量庫、純鍵值庫）全數落後 10 個百分點以上。評測指標固然不能取代維運架構選型，但這些數字確鑿證明了多庫融合設計絕非可有可無的微小改進。

### 記憶範疇分類體系（Scope Taxonomy）

Mem0 依邊界清晰劃分記憶範疇：

- **使用者記憶（User memory）**：跨階段作業持久化，以 `user_id` 為鍵值隔離；
- **階段作業記憶（Session memory）**：僅在單一對話執行緒中存續；
- **Agent 記憶（Agent memory）**：綁定於特定 agent 實例的專屬內部狀態。

每次寫入操作皆必須明確歸屬於某個範疇。檢索時支援跨範疇查詢並可依範疇配置不同權重。若不加思索地將範疇混為一談，極易引發「助理在與 Alice 對話時意外洩漏了 Bob 的專案機密」等重大資安事故。

### 典型架構失效模式

- **Embedding 漂移（Embedding drift）**：在資料量達到前數百條時表現完美的向量檢索，隨著語料庫急遽膨脹，檢索準確率開始嚴重劣化。解法：定期對使用頻率最高的 Top-N 記錄重新計算 embedding。
- **鍵值 Schema 欄位失控膨脹**：`(user_id, type, entity)` 看似簡潔，但隨著內部多個團隊介入，各團隊開始任意擴充私有 `type`。解法：每季對型別定義進行嚴格審計與標準化收斂。
- **圖譜節點爆炸（Graph explosion）**：某個雜訊過大的提煉器在單次訊息中一口氣生成了 50 條邊。解法：為單次 `add` 呼叫設定圖譜寫入上限，主動拋棄低置信度的關聯邊。

## Build It｜動手實作

`code/main.py` 以純 Python 標準函式庫實作了三合一記憶體模式：

- `VectorStore`：以輕量 Token 重疊相似度作為 embedding 的教學替代方案。
- `KVStore`：以 `(user_id, fact_type, entity)` 為鍵值的字典查表。
- `GraphStore`：包含 (subject, relation, object, valid) 的強型別圖譜邊集合。
- `Mem0`：頂層統一 Facade 門面，封裝 `add()`、`search()`、融合評分與範疇感知檢索。
- 完整的多使用者、多階段作業實際對話日誌驗證。

運行實驗：

```
python3 code/main.py
```

輸出會展示：三條各自獨立的回想路徑，以及最終融合後的 Top-k 綜合排序結果。嘗試調整 `main()` 最頂端的評分權重數值，親眼觀察排名順序如何即時改變。

## Use It｜實際應用

- **Mem0（Apache 2.0 開源）**：生產就緒。可使用 Postgres + Qdrant + Neo4j 進行私有部署，亦可直接採用雲端代管服務。
- **Letta**：提供三層核心／回想／檔案記憶體體系，支援自帶專屬向量與圖譜後端。
- **Zep**：商用方案，強項在於時態知識圖譜與事實自動提煉管線。
- **自建架構**：適合需要對提煉器邏輯進行嚴格審計（合規需求）或對融合權重具備極致自訂要求（如語音 agent 極度要求時效新鮮度）的團隊。

## Ship It｜交付成果

`outputs/skill-hybrid-memory.md` 能為任何目標環境產出三合一記憶體架構鷹架，內建融合評分器、範疇分類體系與時態失效標記管線。

## Exercises｜練習

1. 將教學向量相似度替換為真實的 embedding 模型（如 sentence-transformers、Ollama 或 OpenAI Embeddings）。在合成的長對話資料集上測量 Recall@10 表現。在經歷 1,000 次寫入後，排名是否發生漂移？
2. 新增時態查詢介面：`search(query, as_of=timestamp)`。僅回傳在該時間點或之前處於有效狀態的記錄。思考三大儲存庫中哪一個需要承受最大的改造成本？
3. 實作衝突偵測器：若進來的新事實與現有圖譜邊產生矛盾，將舊邊標記為無效並同時留存新舊雙方日誌。在「使用者住在柏林」->「使用者搬到了里斯本」情境上進行實測。
4. 擴充融合評分器，納入 `user_feedback` 維度（使用者對檢索結果的比讚回饋）。該如何防範資訊繭房漏洞（agent 變得只檢索那些它過去點過讚的少數記錄）？
5. 研讀 Mem0 官方文件（`docs.mem0.ai`）。將此教學實作無縫改寫為調用 `mem0` 用戶端 API。在相同的 20 個測試查詢上對照其檢索品質。

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際工程意義 |
|---|---|---|
| Hybrid memory | 「向量 + 圖譜 + 鍵值」 | 三大實體儲存庫並行寫入，檢索時實施多路召回融合 |
| Fact extraction | 「記憶提取導入」 | 利用 LLM 將非結構化文字剖析為（實體, 關聯, 事實）三元組的步驟 |
| Fusion scoring | 「綜合相關度排序」 | 相關性、重要性與時效新鮮度三者的加權數學總和 |
| Scope | 「記憶命名空間」 | user / session / agent——決定了誰有權看見哪些記憶的隔離邊界 |
| Mem0g | 「記憶知識圖譜」 | 具備時態有效性標註的強型別實體關聯圖，專門服務多跳推論 |
| Temporal invalidation | 「軟刪除」 | 將相互矛盾的過時舊邊標記為無效，但保留其歷史痕跡以供時態追溯 |
| Embedding drift | 「向量檢索腐化」 | 隨著語料庫急遽膨脹，向量餘弦相似度準確度逐漸劣化的客觀現象 |
