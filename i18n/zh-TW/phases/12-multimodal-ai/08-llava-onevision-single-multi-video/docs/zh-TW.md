# LLaVA-OneVision：單圖、多圖與影片統一於單一模型（LLaVA-OneVision: Single-Image, Multi-Image, Video in One Model）

> 在 LLaVA-OneVision（Li 等人，2024 年 8 月）問世之前，開源多模態世界割裂為不同的專業陣營：專攻單圖的 LLaVA-1.5、專攻多圖的 Mantis 與 VILA、專攻影片的 Video-LLaVA 與 Video-LLaMA。每個專項模型各自在專屬基準上奪冠，卻在其他場景潰不成軍。LLaVA-OneVision 提出了一個革命性觀點：一套精心設計的訓練課綱（curriculum），便能訓練出通吃這三種場景的單一大一統模型；更重要的是，跨場景的湧現遷移效應（將單圖感知力遷移至影片、將多圖推理力遷移至單圖）大幅超越了多個專門模型的能力總和。其工程配方無比簡潔：跨場景維持恆定不變的視覺 token 總預算，外加「單圖 → OneVision 多圖融合 → 影片強化」的明確階段時程。本課深入拆解其預算分配演算法、訓練課綱以及驚豔學界的湧現行為。

**Type:** Build
**Languages:** Python (stdlib, token budget solver + curriculum planner)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 06 (any-resolution)
**Time:** ~180 minutes

## Learning Objectives｜學習目標

- 設計一套在單圖、多圖與影片輸入場景下皆能維持總量恆定的視覺 token 預算配置方案。
- 規劃精確的訓練課綱先後時程，使單圖習得的細微感知力能無損遷移至影片理解，避免災難性遺忘。
- 深入解釋為何在適當課綱的引導下，參數量完全相同的單一通用模型能全面擊潰多個專門特化模型。
- 剖析 LLaVA-OneVision 論文中所揭露的三大自發湧現能力：多視角鏡頭綜合推理、標籤標註提示（set-of-mark prompting）以及 iPhone 截圖代理操作。

## The Problem｜問題

單張影像、多圖對比與動態影片，各自對模型施加了截然不同的架構壓力。

單圖場景渴求高解析度的視覺細節（例如 AnyRes 機制，產生約 2880 個視覺 token），以精確辨識微小文字（OCR）與微觀圖表。每筆樣本的預算為：單張大圖，2880 個 token。

多圖場景需要同時容納多張中等解析度的影像（每張約 576 個 token），以確保跨圖比對與因果推理不會超出 LLM 的 context 視窗上限。每筆樣本的預算為：4 到 8 張圖，每張 576 個，總計 2300 至 4600 個 token。

影片場景則需要採集大量較低解析度的影格（經池化後每幀約 196 個 token），以完整捕捉長時序動態變化。每筆樣本的預算為：8 到 32 幀，每幀 196 個，總計 1600 至 6200 個 token。

若你為各個場景分別訓練獨立模型，只需固定單一預算即可。但若你想打造一個統攬三者的全能模型，就必須確保視覺 token 預算能夠跨場景平滑調度，絕不隨意塞爆底座 LLM 的 context 上限。

在 OneVision 出現前，業內的常規做法是「各司其職，互不相干」。Video-LLaVA 是在影像模型上強行硬塞額外的訓練階段以勉強相容影片；LLaVA-NeXT 則透過切片拼圖擴充了多圖支援。但沒有任何架構能將這三種形態優雅融為一體。

## The Concept｜核心概念

### OneVision 的 Token 預算管理機制

LLaVA-OneVision 大膽制定了一套統一的視覺 token 預算框架——將每筆樣本的視覺 token 總量嚴格錨定在約 3000 至 4000 個 token，並依不同場景進行彈性分配：

- 單圖場景：AnyRes-9 佈局（3×3 網格切片 + 全景縮圖）。每個切片原生為 384 解析度（729 個 patch），隨後施加激進的 2×2 雙線性池化（bilinear pooling）壓縮至每片 182 個 token。總計：9 × 182 + 182 = 1820 個 token。或採用 AnyRes-4 佈局且不池化（每片 729 個 token）= 2916 + 729 個 token。
- 多圖場景：每張圖維持適中解析度（384 解析度，不進行網格切片），保持 729 個 token 不做池化。預算上限為 6 張圖 → 總計 4374 個 token。
- 影片場景：均勻抽樣 32 幀，每幀為 384 解析度，施加激進的 3×3 雙線性池化 → 壓縮為每幀僅 81 個 token。總計：32 × 81 = 2592 個 token。

這套動態分配策略使得總 token 量始終維持在穩定區間內。底座 LLM 永遠不會遭遇破壞 context 視窗的異常批次。視覺編碼器雖為不同場景產出相異的幾何形狀，但 LLM 消化處理的始終是恆定可靠的預算規模。

### 三階段訓練課綱

LLaVA-OneVision 的訓練流程劃分為嚴謹的三大階段：

1. 單圖指令調校（SI 階段，Single-Image SFT）：全數訓練資料皆為單圖搭配文字。在超高畫質 AnyRes 輸入下訓練。此階段的核心目標是建立紮實的底層微觀感知、精準 OCR 以及空間細節識別能力。資料來源包含 LLaVA-NeXT 語料庫與 OneVision 專屬的高畫質單圖資料。
2. OneVision 混合融合階段（OV 階段，OneVision SFT）：等比例混合單圖、多圖以及視訊影格（均勻抽樣幀）。在此統一步調下依上述固定 token 預算進行聯合訓練。此階段教會模型靈活處理異質批次結構。權重不進行任何重設，直接自 SI 階段順暢延續。
3. 任務遷移與落地調校（TT 階段，Task Transfer）：根據具體落地產品的業務偏向（例如側重多圖比對或長影片理解），在特定的目標任務分佈上繼續調校。

關鍵實證：課綱的順序至關重要！若倒過來「先訓影片再訓單圖」或「先訓多圖再訓單圖」，即使總資料量完全相同，模型在單圖上的感知精度也會遭遇嚴重崩潰。論文對此進行了嚴謹的消融驗證。

### 為何訓練課綱能發揮威力

單圖訓練能奠定最堅不可摧的微觀感知基石。Patch token 攜帶著豐富的高頻空間特徵，底座 LLM 在此階段學會了將這些高密度特徵與文字語意深度融合。而多圖與影片則帶來了高階的結構性挑戰（例如「哪張圖對應哪個實體」、「事件的先後因果次序」），若沒有強大的底層感知力作為支撐，模型極難直接習得這些深層結構。

若一開始便將所有場景混在一起從零混訓，模型很容易在微觀感知上欠擬合（因為每個批次中的單圖細節資料被大幅稀釋），並在巨量的多圖與影片中過度擬合粗淺的巨觀格式。最終只會得到一個看似能理解多圖關聯、實則視覺感知極其粗糙的平庸模型。

嚴謹的課綱時程，讓模型先在 SI 階段將感知力打滿，隨後在 OV 階段順理成章地解鎖巨觀組合推理與時序邏輯，兩者相得益彰。

### 跨場景湧現能力

LLaVA-OneVision 論文報告了三項令人矚目的自發湧現能力：

1. 多視角鏡頭綜合推理（Multi-camera reasoning）：模型在訓練時單獨看過多圖與影片，從未見過車載多視角相機的專門格式；但在推論時，它能自然且準確地整合前後左右四個鏡頭的畫面，進行深度的路況因果推理。
2. 標籤標註提示（Set-of-mark prompting）：使用者在影像中的不同物體上用數字方框進行視覺標註；模型能夠準確回答「標籤 3 與標籤 7 之間的相對位置與互動關係」。模型從未針對該標註符號進行專項訓練，此能力完全湧現自空間定位與多圖參照機制的有機結合。
3. iPhone 截圖代理操作（iPhone-screenshot agent）：使用者傳入一張 iPhone 螢幕截圖並詢問下一步操作建議。模型在混合了 UI 截圖、使用者操作影片與多圖操作前後對比的課綱薰陶下，自然展現出強大的行動端代理規劃能力。

這些能力絕非人為預先設計的特定任務，而是豐富課綱在跨模態整合下激發出的自然湧現成果。

### 視覺 Token 空間池化

嚴格維持 token 預算的秘訣在於空間池化。OneVision 在二維 patch 網格上執行雙線性插值（Bilinear interpolation）：將 24×24 = 576 個 patch 壓縮為 12×12 = 144 個（2 倍壓縮），或壓縮為 8×8 = 64 個（3 倍壓縮）。池化運算嚴格在二維空間網格中進行，而非在一維 token 序列上隨意摺疊，從而完好保留了空間局部幾何特性。

針對不同場景選擇何種池化倍率，本質上是一個關鍵超參數：更少池化 = 更多 token = 更豐富細節；更多池化 = 更少 token = 能在 context 中容納更多影格與圖片。

### LLaVA-OneVision-1.5

2025 年發布的後續演進版 LLaVA-OneVision-1.5（arXiv:2509.23661）實現了訓練資料、模型權重與訓練程式碼的「完全純粹開源」。在多項前沿評測上縮小了與專有閉源模型的差距。架構完全未變，核心升級在於課綱進一步最佳化、資料規模擴充以及換裝更強大的語言模型底座。

### 與 Qwen2.5-VL 的設計路線對比

Qwen2.5-VL（第 12.09 課）採取了不同的哲學。它依賴 M-RoPE 與動態 FPS 機制，而非固定空間池化。其 token 消耗隨輸入內容自然浮動——1 分鐘的長影片所佔用的 token 遠高於 5 秒短片。LLaVA-OneVision 堅持總預算恆定並依場景動態調校池化倍率。兩種路線皆能成立：Qwen 追求極致彈性，OneVision 則追求系統延遲與成本的絕對可預測性。

## Use It｜實際應用

`code/main.py` 實作了一套針對 OneVision 風格 VLM 的課綱與 token 預算排程器。給定單樣本的總 token 預算上限與目標業務場景比例（例如 40% 單圖、30% 多圖、30% 影片），它能：

- 自動為每個場景精確配置輸入解析度、空間池化倍率與視訊幀數。
- 驗證所有場景是否皆嚴格受限於統一的 token 預算之內。
- 估算預期的視覺 token 數量、LLM 運算開銷（FLOPs），並精確標註哪些場景的 token 密度可能偏低。
- 輸出逐階段（SI → OV → TT）的完整訓練時程安排表。

在規劃多模態 fine-tuning 專案或為線上 VLM 推論服務評估每請求伺服器成本時，可隨時運用此工具。

## Ship It｜交付成果

本課產出 `outputs/skill-onevision-budget-planner.md`。給定目標業務場景分佈與單請求 token 預算上限，它將輸出最佳的 AnyRes 切片倍率、逐幀池化參數、視訊抽樣幀數以及三階段課綱的混合權重比例。在訓練或調校跨場景通用多模態模型時，此工具是不可或缺的決策指南。

## Exercises｜練習

1. 假設你的線上產品負載包含 80% 單圖、10% 多圖（2 到 4 張）以及 10% 影片（8 到 16 幀）。請為其量身規劃一套 token 預算體系。從低頻多圖中省下的寶貴 token 配額，你該如何重新投資以極大化系統價值？

2. 閱讀 LLaVA-OneVision 論文第 4.3 節關於湧現能力的論述。試著提出第四種這套課綱理應能激發、但論文尚未正式報告的潛在湧現技能。

3. 假設將訓練課綱的順序調換——改為先訓練多圖，再訓練單圖，最後訓練影片。請預測哪些特定的基準評測會遭遇嚴重滑坡，並說明其背後的技術成因。

4. 論文中指出其影片基準僅在每段影片抽樣 8 幀的設定下完成訓練。這套權重能否直接泛化至推論階段長達 30 秒的複雜視訊中？最先撞牆崩潰的會是 token 預算還是長程時序邏輯？

5. 將 24×24 個 patch 透過雙線性池化壓縮至 12×12，在每個維度上帶來了 4 倍的空間縮減。以純 Python 標準函式庫實作該池化演算法，並驗證每個 2×2 區塊的數值平均是否與雙線性輸出的幾何中心吻合。

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| OneVision scenario | 「單圖、多圖或影片」 | 通用多模態模型所同時處理的三大核心輸入形態；跨形態維持總預算恆定 |
| Token budget | 「單樣本 Token 配額」 | LLM 在單一訓練或推論樣本中允許看見的視覺 token 總上限，通常設定為 3000 到 4000 |
| Curriculum | 「進階訓練課綱」 | 「單圖 → 多圖混合 → 影片遷移」的循序訓練順序，專為激發跨任務能力遷移而設計 |
| Bilinear pooling | 「空間 Token 壓縮」 | 在二維 patch 網格上套用雙線性插值以降低 token 數量，同時嚴格保留空間局部幾何特性 |
| Emergent skill | 「未經特化自然學會」 | 在推論階段自發展現、且未曾出現在特定訓練資料中的高階跨模態推理能力 |
| AnyRes-k | 「k 片切片拼圖」 | 包含 k 個固定尺寸的局部高畫質切片加上一張全景縮圖的佈局策略，常見 k ∈ {4, 9} |
| Task transfer | 「跨場景技能遷移」 | 藉由共用的底座骨幹，將在單圖上習得的微觀感知力無縫傳遞至視訊理解的遷移效應 |
