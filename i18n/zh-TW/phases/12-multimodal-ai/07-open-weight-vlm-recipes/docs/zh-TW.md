# 開源 VLM 配方：關鍵影響因子全解析（Open-Weight VLM Recipes: What Actually Matters）

> 2024 至 2026 年的開源 VLM 文獻宛如一片龐雜的消融實驗（ablation）表格森林。蘋果的 MM1 測試了 13 種影像編碼器、連接器與資料配比的排列組合；艾倫人工智慧研究所（Allen AI）的 Molmo 證明了精細的人工圖片說明遠勝過 GPT-4V 的知識蒸餾；Cambrian-1 展開了 20 多種編碼器的直接對決；Idefics2 形式化了五維設計空間；Prismatic VLMs 則在受控基準下嚴格對比了 27 種訓練配方。撥開所有喧囂雜音，少數結論跨越論文屹立不搖：影像編碼器的重要性遠高於連接器架構、資料混合比兩者更關鍵，而詳盡的人工圖片說明則徹底擊潰了蒸餾合成資料。本課為你徹底讀懂這些關鍵表格，省去重複踩坑的百萬算力代價。

**Type:** Learn + lab
**Languages:** Python (stdlib, ablation table parser + recipe picker)
**Prerequisites:** Phase 12 · 05 (LLaVA baseline)
**Time:** ~180 minutes

## Learning Objectives｜學習目標

- 掌握 VLM 五維設計空間架構：影像編碼器、連接器、LLM 底座、資料混合配比、解析度訓練時程。
- 讀懂 MM1、Idefics2 與 Cambrian-1 的消融實驗表格，並準確預測調整哪項參數能有效拉動特定基準測試。
- 給定算力預算與目標任務分佈，為全新的 VLM 規劃最佳工程配方（編碼器、連接器、資料、解析度）。
- 深入解釋為何在相同的 token 數量下，精細的人工圖片說明在品質上全面碾壓 GPT-4V 蒸餾資料。

## The Problem｜問題

當今存在數百個開源 VLM。然而「尚可」與「頂尖（SOTA）」之間的巨大鴻溝，往往根本不在於模型架構本身，而在於訓練資料品質、解析度排程規劃以及視覺編碼器的選型。當模型表現不如預期時，若能清楚知道該優先調整哪一個旋鈕，便能為團隊省下動輒數百萬 GPU 小時的昂貴試錯代價。

2023 年的第一波浪潮（LLaVA-1.5、InstructBLIP、MiniGPT-4）大多採用簡單的圖文對預訓練加上 LLaVA-Instruct-150k。這是不錯的起步基準線，但其 MMMU 評測分數普遍在 35% 左右遭遇天花板。

2024 年的第二波浪潮（MM1、Idefics2、Molmo、Cambrian-1、Prismatic VLMs）進行了地毯式的消融實驗。其揭示的實證結果既令人意外，又極具工程實務價值。

## The Concept｜核心概念

### 五維設計空間

Idefics2（Laurençon 等人，2024）精闢地定義了這五大維度：

1. 影像編碼器（Image encoder）：CLIP ViT-L/14、SigLIP SO400m/14、DINOv2 ViT-g/14、InternViT-6B 等。各編碼器在 patch 尺寸、解析度與預訓練目標上各有千秋。
2. 連接器（Connector）：雙層或四層 MLP、Q-Former（32 個 query 加交叉注意力）、Perceiver 重取樣器（64 個 query）、C-Abstractor（卷積加雙線性池化）。
3. 語言模型底座（Language model）：Llama-3 8B / 70B、Mistral 7B、Phi-3、Gemma-2、Qwen2.5 等。LLM 的參數量主導了全系統最核心的運算與記憶體開銷。
4. 訓練資料（Training data）：圖文配對（CC3M、LAION）、交錯圖文網頁（OBELICS、MMC4）、指令對話（LLaVA-Instruct、ShareGPT4V、PixMo、Cauldron）。
5. 解析度時程（Resolution schedule）：固定 224/336/448、AnyRes 動態切片、原生動態解析度；在訓練過程中循序提升（ramped）或全程恆定。

每個正式環境的 VLM 都必須在這些維度上做出抉擇。實證表明，MMMU 成績的絕大部分變異，皆由維度 1（編碼器）、維度 4（資料）與維度 5（解析度）所主導——而不是取決於你挑選了多花俏的連接器。

### 維度一：編碼器遠比連接器重要

蘋果 MM1 論文第 3.2 節明確指出：僅將視覺編碼器從 CLIP ViT-L/14 換成 SigLIP SO400m/14，MMMU 分數便直接提升了 3 個百分點以上。然而將連接器從極簡的 MLP 更換為複雜的 Perceiver 重取樣器，帶來的提升卻不足 1 個百分點。Idefics2 亦復現了完全相同的現象：SigLIP 明顯優於 CLIP；而在相同 token 數量下，Q-Former ≈ MLP ≈ Perceiver。

Cambrian-1 的「視覺編碼器對決榜」（Tong 等人，2024）在以純視覺為核心的 CV-Bench 基準上評測了 20 多種編碼器。穩居榜首的是 DINOv2 與 SigLIP 的混合體系；經典 CLIP 僅處於中段班；而 ImageBind 與 ViT-MAE 則排在其後。從 CLIP ViT-L 升級至 DINOv2 ViT-g/14，在 CV-Bench 上帶來了整整 5 到 7 個百分點的巨大躍升。

2026 年開源 VLM 的預設首選編碼器是具備語意與密集特徵雙重優勢的 SigLIP 2 SO400m/14；有時會與 DINOv2 ViT-g/14 的特徵在通道維度拼接融合（Cambrian 的「空間視覺聚合器」即採此策略）。

### 維度二：連接器架構設計幾乎無足輕重

MM1、Idefics2、Prismatic 以及 MM-Interleaved 等論文殊途同歸地達成了同一結論：在固定的視覺 token 數量下，連接器架構的影響幾乎微乎其微。在平均池化 patch 上架構的雙層 MLP，與消耗相同 token 預算的 32-query Q-Former 相比，基準效能差距在一分以內。

真正發揮決定性作用的是 token 數量。更多的視覺 token 意味著 LLM 投入了更多的運算量，在達到收益遞減點之前效能會顯著提升。每張圖 64 個 token 對 OCR 而言遠遠不夠；576 到 1024 個 token 是當前多數開源 VLM 的最佳甜蜜點；而 2048 以上的 token 僅對密集文件與超大圖表理解有實質助益。

因此，Q-Former 與 MLP 的取捨純粹是工程成本問題，而非品質問題：Q-Former 無論輸入圖解析度多高，皆將 token 嚴格限制在 32 到 64；而 MLP 則如實發送所有 patch token。面對超高畫質輸入時，Q-Former 能大幅節省 LLM context 空間；而在普通解析度下，兩者的品質差異完全在誤差範圍內。

### 維度三：LLM 規模決定整體效能天花板

將底座 LLM 從 7B 擴展至 13B，在所有 VLM 論文中皆能穩定為 MMMU 帶來 2 到 4 個百分點的提升。當擴展至 70B 時，幾乎能大幅突破多數基準。多模態模型推理能力的根本上限，直接取決於底座 LLM 本體的文字推理天花板——視覺編碼器僅負責為其餵入訊號，無法憑空代替它進行深層因果思考。

這正是 Qwen2.5-VL-72B 與 Claude Opus 4.7 能夠在 MMMU-Pro 與 ScreenSpot-Pro 上橫掃千軍的核心原因：其背後的語言大腦無比強悍。再精巧的連接器設計，也絕不可能讓一個 7B 的 VLM 越級取代 70B 模型的推理水準。

### 維度四：資料——精細人工說明擊潰合成蒸餾

Molmo 與 PixMo（Deitke 等人，2024）是 2024 年最震撼學界的重大成果。艾倫人工智慧研究所（Allen AI）邀請真人標註員針對每張影像進行長達 1 到 3 分鐘的高密度語音轉文字即時描述，耗時打造出包含 71.2 萬張高畫質長篇說明的影像資料集。其訓練資料中完全沒有使用任何來自 GPT-4V 的合成蒸餾內容。

結果令人震撼：Molmo-72B 在全數 11 項關鍵基準測試上，全面擊潰了擁有 900 億參數的 Llama-3.2-90B-Vision。這一巨大勝差絕非源自模型架構——而是完全由圖片說明品質所決定。詳盡的人工說明每張影像所包含的有效資訊量，是粗淺網路 alt-text 的 5 到 10 倍以上；更重要的是，它具備極其扎實的事實基礎，徹底杜絕了 GPT-4V 蒸餾資料中普遍存在的「二手幻覺」。

ShareGPT4V（Chen 等人，2023）與 Cauldron（Idefics2）亦遵循了相同的原則（混合優質人工標註與精準 GPT-4V 描述）。趨勢無比清晰：在 2026 年的前沿多模態研發中，說明資訊密度 > 說明資料總量 > 廉價的合成蒸餾便利性。

### 維度五：解析度與其訓練時程安排

Idefics2 的消融實驗顯示：將輸入解析度從 384 提升至 448，帶來 1 到 2 個百分點的提升；從 448 透過網格切片拼圖（AnyRes）提升至 980，在 OCR 基準上能再暴增 3 到 5 個百分點。全程維持單一固定解析度訓練，最終準確率容易卡在平原期；而採用循序漸進的時程排程（從 224 啟動訓練，逐步提升至 448 或原生動態解析度），不僅訓練收斂更快，最終達成的天花板也更高。

Cambrian-1 針對「解析度 vs Token 數量」進行了深度權衡實驗：在固定總運算量下，你可以選擇低解析度搭配大量 token，或是高解析度搭配適中 token。實證結論為：高解析度在 OCR 任務上穩操勝券；而在常規自然場景理解中，低解析度搭配充沛的 token 數量則表現更佳。

2026 年正式環境的黃金配方：第 1 階段在固定 384 解析度下快速完成特徵對齊，第 2 階段切換為最高可達 1280 的動態解析度，專攻重度 OCR 與密集資訊解析任務。

### Prismatic 的嚴格對照消融實驗

Prismatic VLMs（Karamcheti 等人，2024）是業內首次在完全嚴格受控環境下隔離各維度的里程碑研究。固定相同的 13B LLM、相同的指令資料、相同的評測協定——每次僅調整單一維度。其變異貢獻度剖析結果如下：

- 每張影像的視覺 token 數量：主導了約 60% 的效能變異。
- 視覺編碼器的選型：主導了約 20% 的變異。
- 連接器架構的設計：僅佔約 5% 的微小變異。
- 其餘所有細節（資料配比、學習率調度器等）：分攤剩下的約 15%。

這份量化歸因給出了文獻中最清晰透徹的工程指引——當你打算最佳化模型時，究竟該優先將時間精力投入何處。

### 2026 年正式環境選型指南

綜合全部實證研究，為 2026 年全新 VLM 專案規劃的最佳預設配方如下：

- 視覺編碼器：採用具備 NaFlex 原生動態解析度的 SigLIP 2 SO400m/14；若需高精度語意分割或物體定位，可在特徵維度拼接 DINOv2 ViT-g/14 的密集特徵。
- 連接器：直接採用作用於 patch token 的雙層 MLP。除非面臨極端苛刻的 token 數量預算，否則請果斷略過 Q-Former。
- 語言模型底座：首選 Qwen2.5、Llama-3.1 或 Gemma 2；注重低成本延遲選 7B，追求極致品質選 70B。
- 訓練資料：以 PixMo + ShareGPT4V + Cauldron 為核心基底，並混入垂直領域特定的專業指令資料。
- 解析度策略：原生動態解析度（長邊設定 min 256、max 1280 像素邊界門檻）。
- 訓練時程規劃：第 1 階段僅更新投影器進行對齊，第 2 階段全參 fine-tuning，第 3 階段針對目標垂直任務進行精細調校。

## Use It｜實際應用

`code/main.py` 是一個消融實驗結果解析器與配方選型推薦工具。它精煉內建了 MM1 與 Idefics2 的核心消融實驗成果，支援以下查詢：

- 「在算力預算 X 與任務目標 Y 下，最佳勝出配方為何？」
- 「若在 7B Llama 上將 CLIP 換成 SigLIP，預期能帶來多少 MMMU 分數增益？」
- 「若想以 80% 的置信度拉升效能，我應該優先針對哪一個維度展開消融測試？」

程式碼將輸出排序後的推薦架構清單、預期基準增益預估，以及清晰的「首選消融維度」工程建議。

## Ship It｜交付成果

本課產出 `outputs/skill-vlm-recipe-picker.md`。給定目標任務分佈、算力預算與推論延遲上限，它將輸出完整的模型訓練工程配方（編碼器、連接器、底座 LLM、資料混合比、解析度時程），並精確附上支撐每項決策的學術消融論文引用出處。徹底防止工程團隊在每次啟動新 VLM 專案時，毫無必要地重複踩坑摸索。

## Exercises｜練習

1. 閱讀 MM1 論文第 3.2 節。在固定 2B LLM 且訓練預算為 5,000 萬張影像的設定下，哪一個編碼器表現最佳？若將底座升級至 13B LLM，該結論是否會翻轉？為什麼？

2. Cambrian-1 發現：拼接 DINOv2 與 SigLIP 的特徵在純視覺評測上顯著擊敗單一編碼器，但在綜合性 MMMU 上卻未見明顯增益。請預測哪些特定任務子集會受益，哪些指標會持平。

3. 你的專案目標是在 2B LLM 上打造專屬的手機 UI 智慧代理。請為其規劃視覺編碼器、連接器、解析度與資料配比。並以具體的論文消融實驗結果為你的每一項選型進行技術論證。

4. Molmo 推出了 4B 與 72B 兩款模型。其中 4B 即可與主流閉源 7B VLM 匹敵；而 72B 則在 11 項基準測試中全面擊潰 Llama-3.2-90B-Vision。這對「LLM 規模瓶頸假說」提供了何種深刻啟示？

5. 請為一個 7B VLM 設計一份嚴謹的消融實驗計畫表，用以徹底隔離「資料混合品質」與「編碼器素質」的獨立貢獻。最少需要規劃幾組訓練運行？請列出該實驗在四個關鍵維度上的具體設定。

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| Ablation | 「控制變因調旋鈕」 | 保持其他所有條件嚴格固定，僅針對單一設計維度進行多組訓練對比的實證研究 |
| Connector | 「模態橋樑／投影器」 | 負責將視覺編碼器輸出映射至 LLM token 空間的可訓練模組（MLP、Q-Former、Perceiver） |
| Detailed human caption | 「高密度密集描述」 | 包含多個完整句子、長達 80 至 300 個 token 的詳盡人工撰寫描述，遠富於網路簡短標籤 |
| Distillation | 「GPT-4V 合成資料」 | 利用能力更強的專有大模型批次生成的訓練資料；極其便利但容易繼承其固有幻覺 |
| AnyRes / dynamic res | 「高畫質動態路徑」 | 透過網格切片拼圖或 M-RoPE 機制，直接吞吐超越編碼器原生解析度大圖的擴展策略 |
| Resolution ramp | 「解析度階梯式學習」 | 訓練初期採用較低解析度快速建立語意對齊，後期提升解析度捕捉細節的時程調度策略 |
| Vision-centric bench | 「純視覺感知基準」 | 如 CV-Bench 或 BLINK 等專門著重嚴苛視覺細節感知，而非依賴語言邏輯推理的評測集 |
| PixMo | 「Molmo 的核心語料庫」 | 艾倫人工智慧研究所打造的 71.2 萬張高密度圖片說明資料集；由人類語音即時轉錄而成 |
