# 多模態 Agent 與電腦操作（Multimodal Agents and Computer-Use, Capstone）

> 2026 年最具顛覆性的前沿產品形態，莫過於能夠親眼看見螢幕截圖、點選按鈕、自主瀏覽網頁介面、填寫表單並端到端閉環完成複雜業務的多模態 Agent。SeeClick 與 CogAgent（2024）奠定了 GUI 定位（GUI Grounding）的原語基石；Ferret-UI 將其拓展至行動端；ChartAgent 則開創了針對圖表的視覺工具調用機制。VisualWebArena 與 AgentVista（2026）是當今前沿模型競相追逐的極限基準——即使是 Gemini 3 Pro 與 Claude Opus 4.7，在 AgentVista 的高難度任務上也僅能取得約 30% 的通關率。這項專題整合了 Phase 12 的所有技術脈絡：高解析度視覺感知（高解析度 VLM）、邏輯因果推理（具備工具呼叫的 LLM）、空間坐標錨定（座標輸出）、長程記憶管理以及嚴苛的端到端評測。

**Type:** Capstone
**Languages:** Python (stdlib, action schema + agent loop skeleton)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 12 · 09 (Qwen-VL JSON), Phase 14 (Agent Engineering)
**Time:** ~240 minutes

## Learning Objectives｜學習目標

- 設計完整的自主多模態 Agent 迴圈：感知（Perceive）→ 推理（Reason）→ 行動（Act）→ 觀察（Observe）→ 循環迭代。
- 建構標準的 GUI 空間定位動作輸出規範（點選座標、文字輸入、畫面捲動、物件拖曳），使 VLM 能夠精確輸出合法 JSON。
- 深入對比純螢幕截圖 Agent、純無障礙輔助樹（Accessibility Tree）Agent 以及兩者融合的雙軌混合 Agent。
- 在 VisualWebArena 具體任務切片上，架設完整的端到端多模態 Agent 自動化評測環境。

## The Problem｜問題

一個典型的線上訂票真實業務：「幫我找一張 4 月 15 日飛往東京、票價在 800 美元以內的靠走道機票，並直接完成預訂。」

一個自主多模態 Agent 必須依序完成：

1. 擷取當前瀏覽器的實體螢幕截圖。
2. 綜合分析「螢幕截圖 + 當前 URL 網址 + 最終業務目標」，產出具體行動計畫。
3. 輸出結構化動作指令：點選特定座標 (x, y)、在指定元素 E 中輸入文字 "Tokyo"、向下捲動畫面、點選單選按鈕。
4. 將動作指令傳送至瀏覽器自動化驅動層執行。
5. 觀察執行後抵達的新狀態（擷取下一幀螢幕截圖）。
6. 反覆循環迭代，直至整個長程目標徹底完成。

鏈路上的每一個步驟皆是一次多模態 VLM 呼叫。VLM 的輸出必須是可嚴格解析的標準 JSON。錯誤會在長時序步長中持續滾雪球累積，因此錯誤自我偵測與容錯恢復機制至關重要。

## The Concept｜核心概念

### GUI 空間定位——核心原語

GUI 空間定位的本質定義是：給定一張螢幕截圖與一句自然語言操作指令，模型必須精準輸出目標點選（或其他操作）的二維物理像素座標 (x, y)。

SeeClick（arXiv:2401.10935）是首個開源的大規模代表作：在海量合成與真實 GUI 標註資料上調校 VLM，使其直接輸出文字化的整數座標 token。這套做法證明了其可行性。

CogAgent（arXiv:2312.08914）進一步引入了 1120×1120 的超高解析度視覺編碼器，專為元素密集的複雜網頁介面量身打造。在網頁導航基準上創下了高達約 84% 的驚人定位成功率。

Ferret-UI（arXiv:2404.05719）則將焦點全面投向行動裝置介面，並深度融合了 iOS 系統底層的無障礙輔助資料。

標準輸出格式通常為結構化 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

其中 `element_desc`（目標元素語意描述）在容錯機制中扮演關鍵角色：當相鄰截圖之間發生輕微捲動偏移時，外圍系統可依據這項語意提示進行動態二次校準定位。

### 動作規範（Action Schema）

一個完備的 GUI 操作動作規範通常包含 6 到 10 種原子動作類型：

- `click`：點選特定座標 (x, y)。
- `type`：在目標輸入框中輸入文字 (text, 可選 x, y)。
- `scroll`：指定方向與像素幅度 (direction, amount) 捲動畫面。
- `drag`：將物件從起點拖曳至終點 (x0, y0, x1, y1)。
- `select`：在下拉式選單中選取特定項目 (option_index)。
- `hover`：將滑鼠懸停於特定座標 (x, y)。
- `navigate`：直接在瀏覽器跳轉至指定網址 (url)。
- `wait`：等待非同步頁面載入特定毫秒數 (ms)。
- `done`：宣告全流程已圓滿完成 (success, explanation)。

Agent 在每個推論時間步輸出一個明確動作。瀏覽器自動化包裝器負責通電執行，並將產生的高畫質新截圖回傳。

### 純螢幕截圖 vs 無障礙輔助樹（Accessibility Tree）

工業界並存兩種輸入模式：

- 純螢幕截圖（Screenshot-only）：僅接收完整點陣圖像，不依賴任何外部結構化資訊。通用性最高；適用於任何作業系統、原生桌面軟體乃至虛擬機環境。
- 無障礙輔助樹（Accessibility tree）：讀取瀏覽器 DOM 或 iOS 系統底層結構化樹狀結構。定位極度精準穩定；但前提是目標環境必須開放完整的無障礙 API。
- 雙軌混合模式（Hybrid）：兩者深度結合。以無障礙樹作為原子動作定位的堅實錨點，以高畫質螢幕截圖作為宏觀語意理解的全局上下文。

當前正式環境的首選是混合雙軌模式。網頁自動化（Selenium / Playwright + Accessibility API）天然具備樹狀結構；而面對複雜桌面軟體時，純視覺截圖則是無可替代的兜底防線。

### 長程時序記憶管理

一個包含 20 步長的操作任務，會連續產出 20 張高解析度截圖。VLM 的 context 視窗會被瞬間擊穿。工業界發展出三種核心壓縮手段：

- 摘要鏈（Summary-chain）：每前進 5 個步驟，對先前已發生的所有操作與狀態變更進行高密度文字摘要，果斷丟棄歷史大圖。
- 抽幀降採樣（Skip-frame）：僅在 context 中保留第一張初始圖、最新當前圖，以及中間每隔 3 步的關鍵狀態圖。
- 工具日誌記錄（Tool-recorded log）：嚴格維護一份由文字記錄的動作歷史日誌；歷史步驟只看文字日誌，不再重新審視過去的截圖。

Anthropic 官方的 Computer-Use API 堅定採用了日誌記錄模式。架構最簡潔，抗干擾穩定性最高。

### 視覺工具調用機制

ChartAgent（arXiv:2510.04514）為複雜圖表理解引入了革命性的「視覺工具調用」範式：局部裁切、動態放大、呼叫 OCR、乃至呼叫專案目標偵測器。Agent 能夠在推理中途輸出「將座標 (100, 200, 300, 400) 區域局部放大並呼叫 OCR 提取數值」這類工具呼叫。外部工具執行完畢並回傳文字數值後，主控 VLM 繼續推進後續推理。

這種模式具備極高的通用性：標籤標註提示、區域高解析度重檢驗以及外部目標偵測器，皆能自然統整於這套「輸出工具呼叫 → 接收結構化回應」的統一協定之下。

### 2026 年權威基準評測體系

- ScreenSpot-Pro：針對約 1,000 張網頁截圖的微觀 GUI 定位測試。開源 SOTA（Qwen2.5-VL-72B）達到約 85%，頂級閉源旗艦約 90%。
- VisualWebArena：端到端真實網頁任務評測（涵蓋電商購物、社群論壇、分類廣告等複雜閉環）。開源 SOTA 僅約 20%，Gemini 3 Pro 約 27%。
- AgentVista（arXiv:2602.23166）：2026 年代難度最高、最殘酷的權威評測集。涵蓋 12 個真實產業領域的高階工作流。頂級旗艦模型僅能拿到 27% 到 40% 的通關率；開源模型普遍在 10% 到 20% 之間掙扎。
- WebArena / WebShop：早期經典基準，已被當前頂級旗艦模型普遍刷爆飽和。

### 為何電腦操作依然極度艱鉅

當前限制自主 Agent 落地應用的四大核心瓶頸：

1. 極致微觀的空間定位精確度：在行動端介面上，「準確點選右上角那個微小的關閉按鈕 X」依然存在高頻落空。
2. 超長時程的規劃能力維持：在連續執行超過 10 步動作後，Agent 容易發生「目標漂移」，遺忘最初的真實目的。
3. 容錯與自癒能力嚴重不足：一旦某一動作意外點錯（按到了錯誤的彈出視窗），模型鮮少具備自動偵測並自發回滾自癒的訓練經驗。
4. 跨頁面與多分頁狀態同步：在多個分頁之間切換或填寫跨步驟長表單時，極易遺失狀態上下文。

前沿研究的攻堅方向：專屬階層式記憶架構、顯式重規劃演算法，以及利用多模態一致性進行「動作後成果自動驗證」。

### 專題實作目標（Capstone Build-It）

本專題將打造一個完整的電腦操作 Agent：

1. 讀取模擬訂票網站的 HTML 結構與實體螢幕截圖。
2. 自主規劃多步驟長程操作序列：檢索輸入 → 條件篩選 → 填寫個人表單 → 確認送出。
3. 嚴格輸出符合規範的結構化 JSON 動作指令。
4. 在固定的 10 項真實評測任務切片上，全面量化端到端執行成功率。

## Use It｜實際應用

`code/main.py` 包含了專題的核心鷹架實作：

- 涵蓋 10 種標準原子動作的完整 JSON Action Schema 規範。

- 完整的 Agent 自主運作迴圈骨架：接收環境狀態 → 輸出動作決策 → 通電執行 → 循環迭代。
- 包含 10 個合成頁面任務的微型評測集，用於精確衡量端到端閉環任務成功率。
- 內建動作執行失敗時的錯誤捕捉與自發容錯恢復鉤子（Hook）。

## Exercises｜練習

1. 在現有的動作規範中擴充一個 `screenshot_region` 工具（支援局部裁切與二次高畫質放大）。哪些具體任務能從這項新工具中獲得顯著準確率提升？

2. 閱讀 AgentVista 論文（arXiv:2602.23166）。描述其中通過率最低的任務類別為何，並深入分析為何當前最強旗艦大模型在此類任務上依然頻繁折戟。

3. 長程記憶壓縮演算法實作：設計一個摘要鏈演算法，要求在 context 中最多僅保留 ≤ 4 張即時截圖，其餘所有歷史步驟皆壓縮為精確的文字操作軌跡。

4. 建構自發錯誤恢復鉤子：當 Agent 輸出的點選動作因目標按鈕不可見而執行失敗時，設計一條引導 Agent 自主進行「向上捲動畫面以重新尋找按鈕」的重規劃邏輯。

5. 針對 10 項真實網頁自動化任務，深入對比「純截圖模式的 Claude 4.7」與「截圖加無障礙樹混合模式的 Qwen2.5-VL」。分析何者在不同任務類型上各具勝場。

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| GUI grounding | 「點選座標定位」 | 模型針對螢幕截圖上的特定自然語言指令，精確輸出目標元素二維物理座標 (x, y) 的能力 |
| Action schema | 「動作協定規範」 | 嚴格規範合法動作類型（點選、輸入、捲動、拖曳等）及其參數欄位的 JSON 格式定義 |
| Accessibility tree | 「無障礙輔助樹」 | 由瀏覽器 DOM 或作業系統底層 API 匯出的機器可讀 UI 階層結構，具備極高的語意確定性 |
| Hybrid agent | 「雙軌混合 Agent」 | 同時接收點陣截圖與無障礙結構樹的 Agent；在穩定性與泛化性上顯著超越單軌模式 |
| Visual tool use | 「視覺工具主動調用」 | Agent 在執行長程規劃期間，主動呼叫外部視覺工具（局部放大、OCR、目標偵測）輔助決策 |
| Summary-chain | 「時序記憶摘要鏈」 | 週期性以高密度文字摘要替換歷史長截圖序列的記憶體管理策略，防止 context 爆炸 |
| VisualWebArena | 「網頁端到端基準」 | 2024 年發布的權威真實網頁端到端操作評測集，全面考驗多模態大模型的長程閉環能力 |
| AgentVista | 「2026 年極限挑戰基準」 | 涵蓋 12 個真實產業領域超長工作流的極限評測集；當前頂級旗艦模型通關率僅約 30% |
