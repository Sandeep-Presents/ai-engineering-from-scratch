# 音訊語言模型：從 Whisper 到 Audio Flamingo 3 的演進脈絡（Audio-Language Models: the Whisper to Audio Flamingo 3 Arc）

> Whisper（Radford 等人，2022 年 12 月）讓語音辨識成為已解決的問題——68 萬小時弱監督多語言音訊、極簡的編碼器—解碼器 Transformer，以及一項讓後續所有 ASR 論文都引用的評測基準。然而「語音辨識」絕不等於「聽覺推理」。詢問「這段錄音中出現了哪些樂器」、「說話人當下流露何種情緒」或「第 3 分鐘發生了什麼」，需要的是音訊理解，而非單純的語音轉文字。Qwen-Audio、SALMONN、LTU 以及 NVIDIA 的 Audio Flamingo 3（AF3，2025 年 7 月）一步步建立了這套強大堆疊：保留頂級 Whisper 編碼器、外加專屬音訊 Q-Former、在大量音訊指令資料上展開訓練，並引入音訊思維鏈推理機制。本課帶你完整走通這條波瀾壯闊的技術演進脈絡。

**Type:** Build
**Languages:** Python (stdlib, log-Mel spectrogram + audio Q-former skeleton)
**Prerequisites:** Phase 6 (Speech and Audio), Phase 12 · 03 (Q-Former)
**Time:** ~180 minutes

## Learning Objectives｜學習目標

- 從連續原始波形計算 Log-Mel 頻譜圖：視窗分段、快速傅立葉轉換（FFT）、Mel 濾波器組與對數壓縮轉換。
- 深入對比各音訊編碼器方案：Whisper 編碼器、BEATs 以及 AF-Whisper 混合架構，並掌握各自的最佳適用場景。
- 建構專屬音訊 Q-Former：利用 N 個可學習 query 向量對頻譜圖特徵切片進行精準交叉注意力檢索。
- 深入解釋「串接式管線（Whisper 先轉文字再交 LLM）」與「端到端音訊 LLM」在架構上的根本分野，並論證為何端到端架構在聽覺推理任務上展現出顯著的規模擴展優勢。

## The Problem｜問題

語音辨識已被 Whisper 解決。將音訊轉錄為文字如今已淪為隨處可得的日常基礎設施。然而，這類技術的邊界僅止於「轉錄文字」。若模型無法對聽到的內容進行推理——時間資訊、說話人、情緒、音樂結構、環境聲音——單純的逐字稿根本無法支撐起真正智慧化的產品功能。

三種直觀的工程架構路線：

1. 串接式管線（Cascade）：Whisper 負責語音轉錄，隨後由純文字 LLM 對逐字稿進行文字推理。在純說話錄音場景下表現極佳；但面對背景音樂、環境聲響、多說話人重疊發言或微妙語氣情緒時則徹底抓瞎。

2. 端到端音訊大型語言模型（End-to-end audio-LLM）：音訊編碼器將聲音特徵直接映射為音訊 token 餵入 LLM，完全跳過中間的文字轉錄步驟。保留聲學資訊（說話人特質、情緒共鳴、空間環境音）。但需要新的訓練資料。

3. 混合架構（Hybrid）：音訊編碼器搭配文字解碼器，既能精確轉錄文字，又能直接對聲音進行推理。Qwen-Audio 與 Audio Flamingo 皆選擇了此項技術路線。

## The Concept｜核心概念

### Log-Mel 頻譜圖：核心音訊輸入特徵

幾乎所有現代前沿音訊編碼器皆始於同一項基礎聲學特徵：Log-Mel 頻譜圖（Log-Mel Spectrogram）。

1. 將原始音訊重新取樣至 16 kHz 取樣率。
2. 執行短時傅立葉轉換（short-time Fourier transform, STFT）：採用 25 毫秒視窗長度、10 毫秒步長。
3. 計算 FFT 複數結果的絕對幅值（Magnitude）。
4. 套用 Mel 濾波器組（通常配置 80 個三角濾波器，在 0 至 8000 Hz 區間呈對數非線性排布），將物理頻率扭曲映射為貼合人類聽覺感知的 Mel 尺度。
5. 進行動態範圍對數壓縮（計算 log(1 + x)）。

最終產物：一個形狀為 (T, 80) 的二維實數特徵矩陣，其中 T 為時間影格總數。對於一段 30 秒長度、影格率為 100 Hz 的短音訊，其矩陣形狀為 (3000, 80)。

### Whisper 編碼器架構

Whisper 的編碼器本質上是一個 12 層的 ViT 風格 Transformer，它將 Log-Mel 頻譜圖視為沿時間軸展開的連續特徵向量序列。其輸出端為每個時間影格產出一個豐富的隱藏狀態向量。

在標準自動語音辨識（ASR）任務中，Whisper 的解碼器是一個交叉注意力 Transformer，以編碼器輸出為條件自回歸生成文字 token。這是經典的編碼器—解碼器架構。

而在音訊語言模型（ALM）的架構中，我們將 Whisper 的編碼器特徵抽取出來，作為外部大型語言模型（如 Llama 或 Qwen）的直接輸入。典型設計為：凍結 Whisper 編碼器、加裝可訓練的音訊 Q-Former，並搭配凍結或經過調整的底座 LLM。

### BEATs 與專屬音訊特徵編碼器

Whisper 深度偏向人類說話語音資料。面對純音樂與複雜環境噪音時，其表徵能力明顯衰退。

BEATs（Chen 等人，2022）是一款在龐大音訊資料庫 AudioSet 上進行自我監督預訓練的專屬音訊 Transformer。在相同參數量下，它對音樂與環境聲音的捕捉優於 Whisper。

AF-Whisper（Audio Flamingo 3 採用的混合編碼器）：將 Whisper 與 BEATs 的特徵串接作為音訊輸入。Whisper 提供語言訊號，BEATs 提供聲學訊號。

### 音訊專屬 Q-Former

其運作模式與視覺領域的 BLIP-2 Q-Former 完全同構。一組固定數量（通常設定為 32 或 64 個）的可學習 query 向量，對音訊編碼器輸出的長時序頻譜影格進行深入的交叉注意力檢索。這組 query 最終轉化為音訊 token，直接餵入底座 LLM 進行思考。

在特徵對齊階段：僅訓練 Q-Former，在大規模音訊—文字配對語料（AudioCaps、Clotho）上計算對比損失與音訊說明生成損失。在後續指令調整階段：解凍底座 LLM，並以指令資料訓練。

### 演進浪潮——SALMONN、Qwen-Audio 與 AF3

SALMONN（Tang 等人，2023）：「Whisper + BEATs + Q-Former + LLaMA」架構。首款展現出嚴謹跨模態聽覺推理能力的開放音訊大型語言模型。在 MMAU 評測上取得約 0.55 的綜合基準分。

Qwen-Audio（Chu 等人，2023）：採用相似架構，在更豐富的音訊語料庫上訓練，並針對多輪對話調整。MMAU 分數約為 0.60。

LTU（Listen, Think, Understand，Gong 等人，2023）：專門建構了強調顯式邏輯因果推導的音訊資料集，重點探索聲音上的思維鏈（CoT）推理。規模較小，但更聚焦。

Audio Flamingo 3（AF3，Goel 等人，2025 年 7 月）：當前開放模型中的頂級代表。採用 80 億參數的 Qwen2-7B 作為底座大腦、Whisper-large 拼接 BEATs 作為雙核編碼器、64 個 query 的進階音訊 Q-Former，並以超過 100 萬組音訊—文字指令配對資料訓練。MMAU 綜合評測達到 0.72，在數項子評測上與頂級閉源旗艦相當。

AF3 同時引入了「按需啟動的音訊思維鏈」機制：模型在給出最終答案前，可選擇性輸出顯式的中間思考 token（例如「讓我先逐步辨識這段音訊中出現的各項樂器：……」）。在複雜音訊推理任務中，開啟思考模式能帶來 3 到 5 個百分點的顯著準確率提升。

### 串接式 vs 端到端架構深度對決

傳統串接式管線：

1. 先由 Whisper 將語音訊號強制轉錄為純文字。
2. 再交由純文字 LLM 對逐字稿進行理解分析。

此架構在「幫我摘要這段 Podcast」的場景下效果很好。但在以下關鍵維度上會失效：
- 「這首歌傳達了何種情緒？」——情緒深植於配器、調性與人聲嘶吼中，文字根本無法表達。
- 「當前說話的是愛麗絲還是鮑伯？」——這需要說話人辨識。
- 「爆炸聲究竟發生在第幾分第幾秒？」——逐字稿徹底抹殺了精確的物理時序時間戳記。
- 「這段音訊是真實人聲還是 AI 偽造的 Deepfake？」——Deepfake 偵測需要聲學特徵，純文字無法提供線索。

端到端音訊大型語言模型保留了聲學訊號。Qwen-Audio 與 AF3 能夠原生處理音樂結構、環境異音與細微人類情感。

### 2026 年正式環境選型指南

為全新的音訊理解產品規劃架構時：

- 若目標是語音轉錄，且完全不涉及音樂或情緒推理：選用串接式管線（Whisper + LLM）。架構最輕快、推論最經濟。
- 若需求涉及音樂、情緒、多說話人或複雜音訊推理，則採用 AF3 或 Qwen-Audio 家族。能力較強。

串接式管線更便宜、架構也更簡單；端到端架構的能力更強。

### MMAU——權威音訊推理評測基準

MMAU（Massive Multimodal Audio Understanding）是 2024 至 2025 年的音訊推理基準測試：

- 涵蓋人類語音、音樂旋律與環境噪音三大領域的 10,000 道深度音訊文字問答題。
- 全量檢驗分類識別、時間軸定位、因果推導與開放式複雜問答。
- 專門精準打擊傳統串接式管線體系性無法解答的盲區題目。

當前開放模型中的最強模型（AF3）得分為 0.72；閉源頂級旗艦（Gemini 2.5 Pro、Claude Opus 4.7）約在 0.78 左右。開放與閉源之間的鴻溝明顯小於 VideoMME 等影片領域，這標誌著開放音訊大型語言模型正在成熟。

## Use It｜實際應用

`code/main.py` 完整展示了：

- 以純 Python 標準函式庫實作 Log-Mel 頻譜圖計算核心：包含視窗分段、樸素離散傅立葉變換（DFT）與 Mel 三角濾波器組矩陣運算。
- 音訊 Q-Former 骨架：給定編碼器輸出的長時序影格特徵，計算 Q、K、V 矩陣、交叉注意力權重，並輸出 N 個濃縮後的音訊 token。
- 在微型玩具任務上展示串接式管線與端到端音訊大型語言模型的行為差異。

## Exercises｜練習

1. 針對一段長度為 30 秒的音訊剪輯，在 16kHz 取樣率、25ms 視窗長度、10ms 步長、80 個 Mel 頻帶的設定下，精確計算其產生的 Log-Mel 頻譜圖維度大小。若取樣率升級至 48kHz，該特徵矩陣的維度會發生何種變化？

2. 為何 Whisper 在純音樂旋律上的表現差強人意？相較之下，BEATs 捕捉到了哪些 Whisper 內部完全缺失的聲學維度？

3. 針對音訊 Q-Former，配置 64 個 query 相比 32 個 query，在何種複雜度的任務上才能展現出顯著的性價比？在何種情況下採用 32 個 query 是更明智的精簡選擇？

4. 閱讀 AF3 論文第 4 節關於「按需啟動思維鏈」的論述。列舉三種最能從「先思考後回答」模式中獲得巨大準確率增益的典型音訊任務。

5. 設計一個利用 AF3 輸出特徵進行多說話人自動分離標註（Diarization）的極簡工程管線。模型在遇到說話人交替轉換時，該如何透過特定的結構化標籤予以明確標示？

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| Log-Mel spectrogram | 「Mel 聲學頻譜圖」 | 原始音訊經 STFT 變換並透過 Mel 濾波器組壓縮後形成的二維（時間, 頻率）特徵矩陣 |
| Audio Q-former | 「音訊特徵濃縮器」 | 透過交叉注意力將長時序音訊頻譜特徵壓縮為固定數量 query 向量的資訊瓶頸模組 |
| Cascaded | 「先轉文字再思考」 | 先由 ASR 轉錄為逐字稿、再交由 LLM 推理的串接管線；不可避免地徹底遺失原始聲學細節 |
| End-to-end | 「端到端原生音訊大型語言模型」 | 音訊特徵藉由專屬 Q-Former 直接注入 LLM 內部進行思考；完好保留情緒與聲學細節 |
| BEATs | 「音訊界的自監督聲學骨幹」 | 在 AudioSet 巨量語料上進行自監督預訓練的專屬音訊 Transformer，音樂與環境音感知極強 |
| MMAU | 「權威音訊推理基準」 | 涵蓋語音、音樂與環境聲響共 10,000 道深度題目的權威評測集，為當前音訊推理黃金標準 |
| On-demand thinking | 「音訊思維鏈推理」 | 模型可選擇性地在最終回答前輸出推理 token；啟用時，複雜任務的準確率可提高 3 到 5 分 |
