# 文件與圖表理解（Document and Diagram Understanding）

> 文件絕非普通照片。一份 PDF、學術論文、商業發票或手寫表單，蘊含著版面排版、表格矩陣、圖表插圖、腳註標註、頁首頁尾以及深層語意結構，這些是常規影像模型完全無法精確捕捉的。在 VLM 出現前，工業界的經典架構是一條長流水線：Tesseract OCR + LayoutLMv3 + 表格啟發式規則抽取。隨後的 VLM 浪潮以端到端「免 OCR（OCR-free）」模型取代了這套體系——Donut（2022）、Nougat（2023）與 DocLLM（2023）直接將像素映射為結構化標記。到了 2026 年，前沿範式已演進為「直接將整頁高畫質影像餵入具備 2576px 原生解析度的 Claude Opus 4.7」，結構化標記輸出唾手可得。本課帶你縱覽文件 AI 的三大世代演進全貌。

**Type:** Build
**Languages:** Python (stdlib, layout-aware document parser skeleton)
**Prerequisites:** Phase 12 · 05 (LLaVA), Phase 5 (NLP)
**Time:** ~180 minutes

## Learning Objectives｜學習目標

- 深入說明文件 AI 的三大演進時代：傳統 OCR 管線、免 OCR 端到端架構以及原生大模型 VLM。
- 剖析 LayoutLMv3 的三大輸入串流：文字文字、版面空間座標（bbox）與影像 patch，以及跨模態的統一遮蓋預訓練機制。
- 深入對比 Donut（免 OCR、影像直接轉結構化 JSON）、Nougat（專攻學術論文轉 LaTeX）、DocLLM（具備版面感知的生成模型）以及 PaliGemma 2（原生 VLM）。
- 針對全新業務情境（商業發票核對、arXiv 論文解析、手寫病歷表單、中文收據發票）進行精準技術選型。

## The Problem｜問題

「理解這份 PDF」看似簡單，實則充滿工程陷阱。文件中的關鍵資訊分散於多個維度：

- 文字本體內容（佔據約 90% 的基礎訊號）。
- 版面排版結構（標題層級、頁尾腳註、側邊欄欄位、雙欄排版）。
- 表格矩陣（列、行、跨欄合併儲存格）。
- 統計圖表與流程插圖。
- 人類手寫附註與簽名。
- 字型與視覺層級（大標題 vs 內文正文）。

傳統單純的 OCR 只管把文字一股腦吐出，徹底抹殺了空間幾何脈絡。一個負責審核發票的系統，必須確切知道「總計：$1,245」出現在右下角結算欄位，而非某個無關痛癢的腳註備註中。

## The Concept｜核心概念

### 第一世代——傳統 OCR 流水線（2021 年前）

經典的階段式串接堆疊：

1. PDF 檔案 → 逐頁彩現為高解析度點陣影像。
2. Tesseract（或商業雲端 OCR 服務）提取純文字，並回傳每個單詞的空間邊界框（bbox）。
3. 版面分析器（Layout Analyzer）識別各區塊類型（標題、表格、段落文字）。
4. 表格結構辨識器專門解析表格行列與跨儲存格關係。
5. 垂直領域業務規則與正則表達式，提取關鍵鍵值對。

在乾淨規範的印刷文字上運作良好；但在面對手寫字、掃描歪斜、複雜巢狀表格以及非拉丁語系文字時極易崩潰。全鏈路中任何一個環節出錯，皆需要手寫額外的例外補丁。

### TrOCR（2021 年）

TrOCR（Li 等人，arXiv:2109.10282）以 Transformer 編碼器—解碼器架構取代了 Tesseract 傳統的 CNN-CTC 結構，在海量合成與真實文字圖像上展開訓練。在手寫字辨識與多語言文字上取得了跨時代的突破。雖然它依然屬於階段式管線中的一個環節（先文字定位，再跑 TrOCR，最後做版面分析），但 OCR 步驟本身的精度得到了革命性提升。

### 第二世代——免 OCR 端到端模型（2022–2023 年）

首批免 OCR（OCR-free）模型提出：徹底跳過文字偵測與定位環節，直接將影像像素端到端映射為結構化標記文字。

Donut（Kim 等人，arXiv:2111.15664）：
- 採用 Swin-B 作為視覺編碼器的 Transformer 編碼器—解碼器架構。
- 輸出端直接產生表單專屬的 JSON、摘要專屬的 Markdown，或任何特定格式。
- 無需前置 OCR、無需版面分析，一步到位。

Nougat（Blecher 等人，arXiv:2308.13418）：
- 專門針對學術論文進行端到端訓練。
- 輸出端直接產生標準的 LaTeX 或 Markdown。
- 完美還原複雜數學公式、雙欄學術排版以及圖表交互。
- 當今幾乎所有解析 arXiv 論文後台皆依賴此模型。

這些模型是高度特化的專才，而非全能通用模型。讓 Donut 解析複雜學術論文會慘遭滑鐵盧；讓 Nougat 審核商業發票同樣力不從心。

### LayoutLMv3（2022 年）

另一條平行的技術流派。LayoutLMv3（Huang 等人，arXiv:2204.08387）保留了前置 OCR，但在內部深度融合了版面空間感知：

- 同時接收三大輸入串流：OCR 文字 token、逐 token 的二維空間邊界框座標，以及原始影像 patch。
- 跨越三大模態的統一遮蓋預訓練目標（遮蓋文字、遮蓋 patch、遮蓋空間座標）。
- 下游廣泛應用於文件分類、資訊實體抽取與表格問答。

LayoutLMv3 是基於 OCR 的文件理解技術的巔峰之作。在標準表單與商業發票評測集上創下了 VLM 時代前的最高精度紀錄。缺點在於前置依賴高精度的 OCR 引擎。

### DocLLM（2023 年）

DocLLM（Wang 等人，arXiv:2401.00908）是 LayoutLM 的生成式孿生版本。它在版面空間 token 的條件引導下自回歸生成文字解答，大幅提升了針對複雜文件自由問答的能力；但依然受限於前置 OCR 輸入。

### 第三世代——原生 VLM 大模型（2024 年至今）

2024 年之後，通用多模態 VLM 的能力水準已足以徹底終結傳統的多階段管線。直接將整頁高解析度影像餵入前沿 VLM，提出問題，即刻取得精準結構化解答。

- LLaVA-NeXT 引入的 336 切片 AnyRes，足以應付常規小尺寸文件。
- Qwen2.5-VL 的原生動態解析度，可原生吞吐 2048 像素以上的大圖。
- Claude Opus 4.7 原生支援 2576 像素超高畫質文件輸入。
- PaliGemma 2（2025 年 4 月）專門針對文件理解與手寫字展開了深度預訓練。

原生 VLM 與傳統 OCR 管線之間的差距迅速縮小。到了 2026 年，原生 VLM 在以下極限維度上全面勝出：

- 場景文字（手寫字與印刷體混排、多國語言雜揉）。
- 帶有跨欄合併儲存格的複雜巢狀表格。
- 穿插於內文正文中的長篇數學方程式。
- 帶有文字註記說明的統計工程圖表。

傳統 OCR 管線依然佔有優勢的領域：

- 每日需處理數千萬頁純掃描文字、對單頁伺服器推論延遲有極限苛求的場景。
- 對確定性要求極高、嚴禁任何模型幻覺的關鍵合規業務。
- 需要具備法律審計溯源能力的嚴格受規管環境。

### Claude 4.7 與 GPT-5 的前沿效能標竿

在 2576 像素原生解析度輸入下，頂級閉源 VLM 的文件理解精度已達到甚至超越了人類專家水準。2026 年初的權威評測成績如下：

- DocVQA：Claude 4.7 達到約 95.1、PaliGemma 2 達到約 88.4、Nougat 約 77.3，傳統 LayoutLMv3 管線約 83。
- ChartQA：Claude 4.7 達到約 92.2，GPT-4V 約 78。
- VisualMRC：Claude 4.7 達到約 94。

專有大模型的領先優勢，主要來自於超大解析度支援與底座強悍的純語言邏輯大腦。7B 開源模型雖稍落後數分，但正在以驚人的速度逼近。

### 數學公式與 LaTeX 結構化輸出

學術論文處理渴求輸出百分之百精準的 LaTeX 方程式。Nougat 從第一天起就以此為核心目標。而專門引入 LaTeX 訓練目標的 VLM（如 Qwen2.5-VL-Math 及 Nougat 衍生體系）同樣能輸出立即可編譯的 LaTeX 程式碼。若未經專項訓練，常規 VLM 輸出的公式往往看似可讀，但在符號語法上存在諸多微小瑕疵。

在 2026 年的學術論文解析生產管線中：標準實務是先由 Nougat 端到端解析全篇 PDF，隨後僅針對包含複雜圖表插圖的特定頁面，呼叫高階 VLM 進行深度補充理解。

### 手寫字辨識的極限挑戰

手寫字依然是文件 AI 中最艱鉅的子任務。在印刷體與手寫字雜揉的場景下（如醫生手寫病歷處方、填寫完畢的申請表單），傳統 OCR 管線在綜合性價比上依然保有競爭力。然而，專門加強手寫辨識訓練的頂級 VLM（如 Claude 4.7 與 PaliGemma 2）正在迅速改寫格局。

### 2026 年最佳工程配方

為全新的文件 AI 系統進行技術選型：

- 每日數百萬張海量純印刷體發票：LayoutLMv3 + 規則解析引擎，極致經濟且具備確定性。
- 複雜混合文件（學術期刊 + 手寫附註 + 非標表單）：原生 VLM（PaliGemma 2 或 Qwen2.5-VL）。
- 大規模 arXiv 論文批次數位化：Nougat 專門處理數學內文，搭配 VLM 處理插圖與圖表。
- 嚴格法律合規審計場景：以傳統 OCR 管線作為主力輸出，搭配 VLM 作為雙重校驗覆核者。

## Use It｜實際應用

`code/main.py` 完整實作了：

- 具備版面空間座標感知的 Tokenizer 原型：傳入（文字, bbox 座標）配對，自動生成 LayoutLMv3 風格的三模態特徵輸入。
- Donut 風格的任務 Schema 產生器：輸出針對標準表單理解的 JSON 模板。
- 橫跨傳統 OCR 管線、Donut、Nougat 與原生 VLM 在單頁文件上的視覺 token 消耗預算量化比對表。

## Ship It｜交付成果

本課產出 `outputs/skill-document-ai-stack-picker.md`。給定具體的文件 AI 專案規格（業務領域、日處理規模、精度要求標準、法律合規約束），它能在傳統 OCR 管線、免 OCR 專項模型與原生多模態 VLM 之間做出權威工程選型推薦。

## Exercises｜練習

1. 假設你的業務系統每天需要處理 1,000 萬張商業發票。請規劃一套能在完全不犧牲精度的前提下，將每頁推論成本極小化的技術架構堆疊。

2. 為何 LayoutLMv3 在結構化表單問答上顯著勝過純 CLIP-VLM，但在自然場景招牌文字識別上卻落後？其額外引入的 bbox 座標流放棄了何種空間靈活性？

3. Nougat 能直接生成 LaTeX。請各提出一個案例：(a) 原生 VLM 在公式輸出精確度上擊敗 Nougat 的典型邊界情境；(b) Nougat 穩操勝券的情境。

4. 閱讀 Google PaliGemma 2 論文（2024 年）。相較於初代 PaliGemma，其在訓練資料中究竟額外注入了何種關鍵資料集，從而顯著拉升了文件與手寫字辨識能力？

5. 設計一套具備法律合規安全邊界的「混合審核雙軌管線」：以確定性 OCR 管線作為第一道主力輸出，以原生 VLM 作為第二道交叉覆核驗證器。當兩者輸出不一致時，你的仲裁演算法該如何設計？

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| OCR pipeline | 「傳統 OCR 串聯堆疊」 | 由「文字偵測 → 文字識別 → 版面分析 → 規則抽取」構成的多階段流水線 |
| OCR-free | 「免 OCR 端到端模型」 | 直接以端到端神經網路將像素映射為結構化標記輸出的模型體系（如 Donut、Nougat） |
| Layout-aware | 「空間版面感知模型」 | 在輸入序列中顯式引入逐詞二維空間邊界框座標的模型（如 LayoutLM 家族） |
| VLM-native | 「原生多模態大模型」 | 直接將整頁高畫質文件影像餵入 Claude 或 Qwen 等大模型，完全跳過中間流水線 |
| DocVQA | 「文件視覺問答權威基準」 | 文件 AI 領域最具代表性、引用率最高的文件圖表問答標準評測集 |
| Markup output | 「結構化標記輸出」 | 模型直接輸出 LaTeX、Markdown 或 JSON 等標準結構化語法，便於下游自動化解析 |
