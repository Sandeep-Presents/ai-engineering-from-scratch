# Qwen-VL 家族與動態 FPS 視訊理解（Qwen-VL Family and Dynamic-FPS Video）

> Qwen-VL 家族——Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）——堪稱 2026 年最具影響力的開源視覺語言模型體系。每一代模型皆做出了一項決定性的架構押注，並在十二個月內引發整個開源生態爭相效仿：藉由 M-RoPE 實現原生動態解析度、具備絕對時間對齊的動態 FPS 取樣、ViT 內部的視窗注意力（window attention），以及結構化的 Agent 工具輸出格式。到了 Qwen3-VL，這套工程配方已徹底臻於成熟：具備 2D-RoPE 的 ViT 編碼器接收原生長寬比輸入、雙層 MLP 投影器銜接強大的 Qwen3 語言大腦，並在訓練階段將 OCR、視覺定位（grounding）與 Agent 行為作為一等公民重點打造。本課按時間順序為你梳理整個家族演進，助你深刻理解為何各個關鍵參數皆定格於今日位置。

**Type:** Learn
**Languages:** Python (stdlib, M-RoPE encoder + dynamic-FPS sampler)
**Prerequisites:** Phase 12 · 06 (patch-n'-pack)
**Time:** ~120 minutes

## Learning Objectives｜學習目標

- 計算 M-RoPE 的三軸旋轉矩陣（時間、高度、寬度），並深入解釋為何同時需要這三個軸向。
- 為目標影片挑選合適的動態 FPS 取樣策略，並在每秒 token 消耗與事件偵測準確率之間進行嚴謹權衡。
- 按時序指認 Qwen-VL 四代模型的關鍵架構升級及其各自解鎖的關鍵能力。
- 介接 Qwen2.5-VL 風格的 JSON Agent 輸出格式，並從多模態模型的回應中精確解析結構化工具呼叫。

## The Problem｜問題

Qwen-VL 於 2023 年 8 月橫空出世，作為對 LLaVA-1.5 與 BLIP-2 的正面回應。Qwen 團隊瞄準了三大核心痛點：解析度極限、影片理解以及結構化輸出。

解析度維度：LLaVA-1.5 固定在 336×336。看生活照片綽綽有餘，但面對一張中文發票或密密麻麻的試算表螢幕截圖時則完全無能為力。Qwen-VL 的首創突破是直上 448×448 解析度並引入空間邊界框座標標註，讓模型具備「精確指出畫面物件」的能力。

影片維度：早期如 Video-LLaMA 等模型只是機械式地逐幀編碼並塞入 LLM，處理短片段尚可，但面對長達數分鐘且「時間維度才是核心訊號」的複雜影片時則徹底失靈。Qwen 團隊渴望打造一個從底層就原生理解時空維度的統一編碼器。

結構化輸出維度：LLaVA 僅能生成自由形式的長文字。但身為一個 Agent，它必須輸出結構化 JSON。Qwen-VL 從預訓練開始就引入了顯式的 JSON 輸出格式與文字化邊界框座標標註。

Qwen-VL 的每一次跨代升級，都在這三大軸向上大幅推進。

## The Concept｜核心概念

### Qwen-VL（2023 年 8 月）

初代 Qwen-VL：以 OpenCLIP ViT-bigG/14 作為視覺編碼器（高達 25 億參數）、相容於 LLaMA 的單步 Q-Former（包含 256 個 query 向量）、Qwen-7B 作為底座語言模型。其核心貢獻為：

- 448×448 輸入解析度（創下當時開源多模態模型的最高紀錄）。
- 視覺定位（Grounding）：在圖文對上展開專項訓練，賦予模型輸出顯式邊界框座標的能力。例如：「The cat is at <box>(112, 204), (280, 344)</box>」。
- 從第 1 天起便深度融合中英雙語聯合訓練。

當時的評測表現：在英文多模態基準上可與 GPT-4V 分庭抗禮，在中文多模態領域則展現絕對統治力。空間座標定位能力的引入更是引發了廣泛震撼。

### Qwen2-VL（2024 年 9 月）——M-RoPE 與原生動態解析度

Qwen2-VL 徹底顛覆了原先固定解析度加 Q-Former 的繁瑣體系，改採原生動態解析度的 ViT 編碼器。關鍵革新包含：

- 原生動態解析度：ViT 原生支援長寬皆為 28 倍數的任意 H×W 影像（採用 patch 14 搭配 2×2 空間合併）。一張 1120×672 的影像（40×24 個合併 patch）直接輸出 960 個視覺 token。零非等比縮放、零切片拼圖、零額外縮圖。
- 多模態旋轉位置編碼（M-RoPE）：每個 token 攜帶三維座標 (t, h, w) 而非傳統一維位置。單圖設定 t=0；影片則令 t = 影格索引。RoPE 依各軸向座標對 Query 與 Key 進行精確頻率旋轉。徹底告別靜態位置 embedding 表。
- 雙層 MLP 投影器：果斷棄用 Q-Former，改在空間合併後的 patch token 上套用雙層 MLP。
- 動態 FPS 影片支援：預設以 1 至 2 FPS 取樣影片，且模型原生相容任意影格總數。

成效驚人：70 億參數的 Qwen2-VL-7B 在多項評測中打平 GPT-4o，更在 DocVQA 上以 94.5% 碾壓了後者的 88.4%。架構底層的典範轉移發揮了決定性威力。

### Qwen2.5-VL（2025 年 2 月）——動態 FPS 與絕對時間對齊

Qwen2.5-VL 將進化焦點全面投向長視訊理解。動態 FPS 不僅僅是「需要時多抽幾幀」那麼簡單，該論文形式化了一整套架構：

- 絕對時間 Token：不再使用模糊的相對影格索引（第 0 幀、第 1 幀……），而是引入精確的時間戳記。例如「在 0:04 時，貓跳了起來」。模型看見的是穿插在視覺影格之間的 `<time>0.04</time>` 顯式時間 token。
- 動態 FPS 調度：慢節奏生活影片以 1 FPS 抽樣；激烈運動場景則提升至 4+ FPS。使用者或調度器可自由指定，M-RoPE 自動適應無礙。
- ViT 內部視窗注意力：空間注意力限制在局部視窗（window）內部以極大化運算吞吐；每隔數層插入一次全域注意力。
- 顯式 JSON Agent 輸出規範：深度訓練於工具呼叫資料：「{\"tool\": \"click\", \"coords\": [380, 220]}」。開箱即可直接驅動 GUI Agent。
- MRoPE-v2 頻率縮放：位置座標隨輸入長度自適應縮放，確保一段長達 10 分鐘的超長影片不會超出高頻旋轉的區間範圍。

評測成效：Qwen2.5-VL-72B 在多數視訊基準上擊潰 GPT-4o，在文件圖表上比肩 Gemini 2.0，並在 GUI 螢幕操作定位（ScreenSpot：84% 準確率 vs GPT-4o 的 38%）上樹立了開源全球新標竿。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是集大成者而非顛覆者：換裝更龐大的語言模型底座（Qwen3-72B）、注入更海量的高質量訓練資料、強化 OCR 解析極限，並透過 Qwen3 特有的「思考模式（thinking mode）」賦予視覺推理更深層的推導能力。ViT 與 M-RoPE 的底層骨架完全保留。該論文將焦點全面置於資料與訓練改進，而非翻新底層架構。

家族演進啟示：到了 2025 年，Qwen-VL 的核心架構已徹底定型。後續世代擴展的是算力與資料規模，而非底層原語。

### M-RoPE 的數學推導

經典一維 RoPE 透過位置座標 `m` 旋轉維度為 `d` 的向量 `q`：

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 則將隱藏維度等分為三個頻帶（band）。假設 `d = 96`：分配 32 維給時間、32 維給高度、32 維給寬度。各頻帶依自身對應的軸向座標各自旋轉。位於座標 (t=5, h=10, w=20) 的 patch，其三個頻帶分別套用 `R_t(5)`、`R_h(10)` 與 `R_w(20)` 的旋轉運算。

文字 token 則設定 `t = text_index, h = 0, w = 0`（或標準化的對應選項），維持向下相容；視訊影格設定 `t = frame_time, h = row, w = col`；單圖則固定 `t = 0`。

核心效益：一套旋轉編碼公式，無需任何條件分岔程式碼或切換位置表，即可完美統一處理文字、靜態圖片與動態視訊。

### 動態 FPS 取樣演算法邏輯

給定長度為 `T` 秒的影片與目標 token 總預算 `B`：

1. 計算預算允許的最大幀率：`fps_max = B / (T * tokens_per_frame)`。
2. 從候選集 `{1, 2, 4, 8}` 中選取滿足 `fps <= fps_max` 的最大可用 FPS。
3. 若畫面動態劇烈（依據光流偵測啟發式或使用者明確指定），調高 FPS；若畫面相對靜止，則降低 FPS。
4. 依選定的 FPS 均勻抽樣影格，並在相鄰影格之間插入 `<time>t</time>` 絕對時間戳記。

Qwen2.5-VL 在預訓練中便已掌握了此項時序關聯；在推論時使用者可透過 `fps` 參數精確控制。一段 60 秒的動作短片在 4 FPS 下、每幀 81 個 token 總計消耗 19,440 個 token，在 32k 的 context 視窗中游刃有餘。

### 結構化 Agent 輸出

Qwen2.5-VL 的訓練特別著重於輸出嚴格符合規範的工具呼叫：

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析過程具備百分之百的確定性：直接對模型輸出執行 JSON.parse 即可。相較於早期需要依賴複雜正則表達式解析「click at (1024, 512)」的脆弱做法，結構化輸出正是 Qwen2.5-VL 在 ScreenSpot 評測從 55% 躍升至 84% 的關鍵轉折。

```figure
mm-mrope-axes
```

## Use It｜實際應用

`code/main.py` 完整實作了：

- 針對混合文字、影像 patch 與視訊影格的打包序列，計算其專屬的 M-RoPE 三維空間旋轉矩陣。
- 動態 FPS 取樣器：給定（影片長度、token 預算、運動劇烈度），自動決策最佳幀率並產出各幀的時間戳記。
- 玩具 Qwen2.5-VL JSON 輸出解析器：精確解析包含空間座標欄位的 Agent 工具呼叫回應。

動手運行該程式碼，親身體驗在一條 5 分鐘影片上，將傳統固定 FPS 切換為動態 FPS 時所帶來的巨大效率飛躍。

## Exercises｜練習

1. 針對隱藏維度為 48（每個頻帶 16 維，底數 theta 為 10000）的設定，手算位於 (t=3, h=5, w=7) 的 patch 的 M-RoPE 旋轉角度。寫出每個頻帶前三對座標的具體旋轉角度數值。

2. 一段長達 10 分鐘的監控攝影機錄影，以 1 FPS 抽樣會產生多少幀？在 384 解析度搭配 3 倍空間池化下，總共會產生多少視覺 token？Qwen2.5-VL 預設的 32k context 視窗能否順暢容納？

3. 針對 30 秒的網球來回對打、30 秒的料理教學展示以及 30 秒的 UI 系統操作錄影，分別規劃合適的 FPS 取樣率。並以動態 FPS 演算法邏輯論證你的決策依據。

4. Qwen2.5-VL 徹底拋棄了 Q-Former。為何在 2023 年必須依賴 Q-Former，而到了 2025 年純 MLP 投影器卻能大獲全勝？（提示：思考訓練資料規模與視覺編碼器本身的表徵素質演進。）

5. 嘗試將三組 Qwen2.5-VL 格式的 JSON 工具呼叫解析為 Python 字典。若模型偶發輸出格式殘缺的 JSON，最常在何處出錯？Qwen 官方手冊推薦了何種容錯恢復策略？

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| M-RoPE | 「多模態 RoPE」 | 將隱藏維度切分為時間、高度與寬度三頻帶的三維旋轉位置編碼機制 |
| Dynamic FPS | 「智慧動態抽幀」 | 依據畫面運動劇烈度、影片總長與 token 預算，為每條影片動態自適應選取取樣幀率 |
| Absolute time token | 「時間戳記標籤」 | 穿插在影格之間的 `<time>t</time>` token，讓模型精確感知絕對秒數而非相對幀數 |
| Window attention | 「局部視窗注意力」 | 將空間自注意力限制在局部小視窗內以暴增運算吞吐；週期性插入全域注意力層 |
| Structured agent output | 「JSON 結構化模式」 | 深度監督模型直接輸出包含座標與工具名稱的標準合法 JSON 格式 |
| min_pixels / max_pixels | 「解析度上下界約束」 | Qwen2.5-VL 提供的每請求調控參數，用以將總像素量與 token 數量限制在安全範圍內 |
| Grounding | 「指認目標座標」 | 模型直接以文字 token 輸出物體邊界框座標的能力；自初代 Qwen-VL 即為核心特色 |
