# InternVL3：原生多模態預訓練（InternVL3: Native Multimodal Pretraining）

> 在 InternVL3 問世之前，幾乎所有開源 VLM 都遵循著同一套三步驟配方：先取一個在數兆文字 token 上訓練好的純文字 LLM，串接一個視覺編碼器，然後調校接縫處。這種做法雖然可行，卻會累積嚴重的「對齊負債（alignment debt）」——純文字 LLM 已在純文字上耗盡了全部預訓練預算，本質上無法將視覺 token 視為一等公民。當你在事後硬生生植入視覺能力時，LLM 必須費力重新學習如何將視覺輸入與文字推理相連結，同時竭力避免遺忘純文字能力。InternVL3（Zhu 等人，2025 年 4 月）果斷拒絕了這種事後拼裝（post-hoc）路線：從預訓練的第 1 步起，文字與多模態資料便緊密交錯、共同參與訓練。最終成果驚豔全場：在 78B 開源參數量下，MMMU-Pro 評測直接打平專有閉源的 Gemini 2.5 Pro。本課深入探討原生多模態預訓練的技術論證，以及當你走向這條路線時，架構層面所發生的深刻質變。

**Type:** Learn
**Languages:** Python (stdlib, training-corpus mixer)
**Prerequisites:** Phase 12 · 05, Phase 12 · 07 (recipes)
**Time:** ~120 minutes

## Learning Objectives｜學習目標

- 解釋為何事後拼裝式 VLM 訓練會持續累積對齊負債，並列舉三大可量化的具體病徵（災難性遺忘、回答漂移、圖文自相矛盾）。
- 深入剖析 InternVL3 的原生預訓練語料混合配比，並說明為何文字、交錯圖文與圖片說明三者的比例至關重要。
- 對比 V2PE（可變視覺位置編碼）與 Qwen2-VL 的 M-RoPE 架構差異。
- 掌握視覺解析度路由器（ViR）與解耦視覺語言部署（DvD）這兩大正式環境部署最佳化技術。

## The Problem｜問題

事後拼裝式（Post-hoc）VLM 訓練是長期以來的預設常規。LLaVA、BLIP-2、Qwen-VL、Idefics——全都是拿一個已經完成預訓練的現成 LLM（Llama、Vicuna、Qwen、Mistral），隨後為其加裝視覺模組。其訓練階段通常如下：

1. 凍結 LLM + 凍結視覺編碼器 + 可訓練投影器，在圖文描述配對上訓練以對齊 embedding 空間。
2. 解凍 LLM，在指令資料（LLaVA-Instruct、ShareGPT4V）上展開訓練。
3. 選用針對特定任務的落地調校。

這種拼裝機制導致了三種顯著的「對齊負債」症狀：

- 災難性遺忘（Catastrophic forgetting）：事後拼裝的 VLM 會嚴重退化純文字能力。GSM8K 數學評測分數暴跌 5 到 10 個百分點；Hellaswag 常識推理分數滑坡；純文字 Agent 行為嚴重劣化。
- 回答漂移（Answer drift）：對同一個視覺問題僅做極其微小的措辭改動，模型便給出截然不同的答案。視覺編碼器與 LLM 之間的連結強度，遠弱於 LLM 自身的文字 token 關聯。
- 圖文自相矛盾（Visual-text inconsistency）：模型能精準描述一張影像中的每個物件，卻在隨後的提問中給出與自身描述直接衝突的荒謬回答。視覺 token 並未如文字 token 那般，深度參與 LLM 內部的自洽性校驗機制。

這些症狀在業界已被充分文獻化。MM1.5 論文第 4 節對此進行了精確量化，LLaVA-OneVision 的消融實驗亦側面印證了這點。原生多模態預訓練正是根治此頑疾的終極解方。

## The Concept｜核心概念

### 原生多模態預訓練

InternVL3 徹底從零開始，在從第 1 步起就具備原生多模態特性的混合語料庫上展開預訓練。其資料混合比為：

- 40% 純文字資料（FineWeb、Proof-Pile-2 等）
- 35% 圖文交錯網頁資料（OBELICS、MMC4 風格）
- 20% 圖文配對資料
- 5% 視訊文字配對資料

視覺 token、文字 token 以及跨模態交互作用，從反向傳播的第一個梯度更新步驟開始，便同時參與同一個損失函式的計算。沒有事後對齊預訓練、沒有凍結投影器的過渡階段，更無需耗費心力去挽救災難性遺忘。

基底模型的預訓練全程為單一連續階段。後續依然會進行指令調校，但基底模型在誕生之初，就已將視覺 token 視為如假包換的一等公民。

### V2PE（可變視覺位置編碼）

Qwen2-VL 使用具有固定軸向分配的 M-RoPE。InternVL3 則提出了 V2PE（Variable Visual Position Encoding）：位置編碼依模態類型（文字、影像、影片）動態彈性分配，並帶有可學習的縮放權重。在實作上：

- 文字 token 獲得一維位置（文字索引序列）。
- 影像 patch 獲得二維空間位置（列, 行）。
- 視訊影格獲得三維時空位置（時間, 列, 行）。

這三種模態共用相同的 RoPE 基礎旋轉頻率，但隱藏維度在各頻帶之間的切分比例不再是僵化寫死，而是作為可學習參數由模型自主最佳化。這使得模型在預訓練期間能自由權衡時間頻率與空間幾何解析度。

V2PE 的消融實驗表明：在完全相同的運算量下，它在視訊基準測試中相較於 M-RoPE 能穩定取得 1 到 2 個百分點的增益。雖非顛覆性劇變，但設計更顯優雅嚴謹。

### 視覺解析度路由器（ViR）

一項極具價值的線上部署最佳化技術。並非所有影像都需要全解析度編碼。一張只包含單一大型物件、細節稀疏的照片，若以 1280px 原生規格編碼，純粹是白白浪費算力。ViR（Visual Resolution Router）是一個輕量級分類器，能在真正進行影像編碼之前，預先預測回答使用者問題所需的最低解析度。

路由機制分為三個等級：低解析度（256 個 token）、中解析度（576 個 token）、高解析度（2048+ 個 token）。在真實正式環境流量中，高達 60% 的請求只需低或中解析度便足以完美解答。總體效益：在維持完全相同品質的前提下，服務推論吞吐量提升了 2 到 3 倍！

### 解耦視覺語言部署架構（DvD）

在部署大型 VLM 時，視覺編碼器對每張影像僅需執行一次前向傳播；而 LLM 則必須為每一個產出的文字 token 執行昂貴的自回歸推論。這兩大元件的硬體效能瓶頸截然不同（視覺端受限於卷積與注意力的 GPU 記憶體頻寬；語言端則嚴重受限於 KV 快取容量）。DvD（Decoupled Vision-Language Deployment）將兩者拆分至不同的專用 GPU 節點上，中間透過串流傳輸傳遞 token。

對於「8B 語言底座 + 4 億參數視覺編碼器」的模型配置，DvD 相較於傳統單卡混合部署，單節點吞吐量幾乎直接翻倍。

### 單階段與多階段預訓練品質對比

InternVL3 最核心的實證戰果：在 78B 參數量下，MMMU-Pro 成績直接追平 Gemini 2.5 Pro；在 38B 下打平 GPT-4o；在 8B 下登頂全球開源 8B 榜首。全部建立在「單階段原生預訓練 + 指令調校」的簡潔配方之上。

「對齊負債假說」得到了量化驗證：在換取同等視覺基準提升的前提下，InternVL3-8B 在純文字基準測試（MMLU、GSM8K）上的分數跌幅，明顯低於事後拼裝式的 Qwen2.5-VL-7B。該模型展現出更強大的全能通用性，正是因為其訓練從第 1 步起就是有機整體，而非兩段拼裝。

### InternVL3.5 與 InternVL-U

InternVL3.5（2025 年 8 月）全面擴展了此配方。沿用原生預訓練思路，注入更多資料與參數量，在各項榜單上持續推升。

InternVL-U（2026 年）則進一步整合了統一生成能力——在相同的骨幹網路之上加裝基於 MMDiT 的影像生成頭。「U」代表「理解（Understanding）+ 生成（Generation）」，朝向類似 Transfusion 的大一統模型（第 12.13 課）邁進。同一個原生預訓練骨幹，能同時支撐理解與生成雙重任務。

### 原生預訓練的工程取捨

原生預訓練並非沒有代價：

- 算力成本：從零訓練一個全新的多模態基底模型，成本等同於從零訓練一個頂級文字 LLM——動輒需要數百萬 GPU 小時。而事後拼裝適應則能直接重用現成的開源 LLM 權重，省去絕大部分昂貴算力。
- 資料稀缺性：大規模圖文交錯語料庫極其罕見。OBELICS 僅包含 1.41 億篇文件；MMC4 僅 5.71 億篇；而純文字語料已動輒突破 15 兆 token。多模態原生預訓練資料的匱乏是無法迴避的硬性瓶頸。
- 底座復用性喪失：原生預訓練意味著你徹底放棄了日後隨意抽換底座語言模型的自由。事後拼裝方式讓你在 Llama-4 問世時，僅需重訓輕量級 adapter 即可快速升級。

InternVL3 押注的信念是：對齊負債的危害遠比喪失復用性更為深重。評測成績證明了這項賭注的正確性；然而高昂的訓練門檻，也阻止了多數中小團隊輕易效仿。在未來的工業生態中，事後拼裝式 VLM 依然會因其極佳的性價比而長期共存。

## Use It｜實際應用

`code/main.py` 是一個訓練語料混合器與 ViR 路由器模擬器。它具備：

- 接收目標語料混合比（純文字%、交錯圖文%、圖文對%、視訊%），精確計算各模態預期的訓練 step 數。
- 在批次查詢分佈下（預設為 50% 低細節、30% 中等、20% 高細節）模擬 ViR 路由決策，並回報動態平均 token 消耗。
- 給定編碼器與 LLM 的 FLOPs，估算 DvD 架構帶來的吞吐量倍增效益。
- 並排印出事後拼裝式與原生預訓練在參數量、算力開銷、資料規模以及對齊負債病徵上的全方位量化對比表。

## Ship It｜交付成果

本課產出 `outputs/skill-native-vs-posthoc-auditor.md`。給定一份擬定的 VLM 訓練計畫，它能客觀審查究竟該選擇原生預訓練還是事後拼裝路線，精準預警對齊負債風險，並提供最佳的語料混合配比建議。在啟動全新開源多模態專案時，它是決定訓練戰略走向的頂級審計工具。

## Exercises｜練習

1. 估算 InternVL3-8B（原生預訓練）與 LLaVA-OneVision-7B（事後拼裝）之間的算力開銷差距。兩者所需的 GPU 小時比例大約為何？是什麼造成了如此懸殊的鴻溝？

2. InternVL3 採用 40% 文字 / 35% 交錯 / 20% 圖文對 / 5% 視訊的混合比。若你的目標產品極度偏向視訊理解，請提出一套全新的混合比，並論證為何基底模型依然必須保留高比例的純文字與靜態圖片說明資料。

3. 閱讀 MM1.5 論文第 4 節關於遺忘現象的量化結果。指出事後拼裝訓練在哪一個基準測試上表現出最嚴重的退化？該退化造成了多大的精度損失？

4. ViR 路由器將 60% 的日常請求分流至低解析度編碼。試問哪些特定類型的提問容易被誤判（原本需要高解析度，卻被誤分流至低解析度）？請列出三種典型的路由器失效場景。

5. DvD 架構將視覺編碼器與語言模型拆分至不同的 GPU 叢集。在何種極端的網路流量分佈特徵下，DvD 不僅無法提升吞吐量，反而會拖慢系統整體效能？

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| Native multimodal pretraining | 「從第 1 步一起從零訓」 | 文字、影像與視訊 token 從訓練第 1 個 step 開始便共同參與損失計算，而非事後拼接 |
| Alignment debt | 「拼裝後遺症」 | 將視覺模態強行拼裝至凍結 LLM 上，所引發的文字能力退化與跨模態自相矛盾等可量化病徵 |
| V2PE | 「動態視覺位置編碼」 | 依據模態類型自適應分配可學習位置編碼權重的機制；為 InternVL3 對 M-RoPE 的進一步改良 |
| ViR | 「解析度智慧路由器」 | 在編碼前預測回答問題所需最低視覺解析度的輕量分類器，大幅節省正式環境推論 token |
| DvD | 「解耦分離式部署」 | 將視覺編碼器與 LLM 拆分部署於不同 GPU 節點並以串流銜接，使大模型推論吞吐量翻倍 |
| InternVL-U | 「理解加生成大一統」 | 2026 年後續演進版本，在原生預訓練骨幹上加裝影像生成頭，兼顧視覺理解與生成雙重任務 |
| Interleaved corpus | 「OBELICS / MMC4 語料」 | 依照自然真實排版圖文交錯排列的網頁文件集合；為原生多模態預訓練的核心基石燃料 |
