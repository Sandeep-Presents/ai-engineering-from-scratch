# 全能 Omni 模型：Qwen2.5-Omni 與「思考者—發言者」架構分離（Omni Models: Qwen2.5-Omni and the Thinker-Talker Split）

> GPT-4o 於 2024 年 5 月推出的產品展示震撼業界，其顛覆性並非單純源於底層模型規模，而是源於前所未有的產品形態——一個即時語音介面：你開口說話、攝影機同步看見畫面，而模型在不到 250 毫秒內即時自然回應。開源生態在整個 2024 與 2025 年全力奔跑以達成此產品體驗。Qwen2.5-Omni（2025 年 3 月）是這場競賽中的標準開源參考設計：將系統拆解為「思考者（Thinker，負責高階推理的文字生成 Transformer）」與「發言者（Talker，負責平行串流合成的語音 Transformer）」，中間透過即時串流語音 token 緊密相連。Mini-Omni 將其精簡、Moshi 逼平其極限延遲、GLM-4-Voice 則在中文語音對話上大展身手。本課深入解剖「思考者—發言者」分離架構，並精算讓即時雙向語音對話得以成立的苛刻延遲預算。

**Type:** Build
**Languages:** Python (stdlib, streaming pipeline latency simulator + VAD loop)
**Prerequisites:** Phase 12 · 19 (audio-LLMs), Phase 12 · 16 (any-to-any)
**Time:** ~180 minutes

## Learning Objectives｜學習目標

- 將多模態推論管線拆解為「思考者（文字推理）」與「發言者（語音合成）」，並深入解釋為何平行串流管線能順暢運作。
- 逐一拆解對話式即時互動鏈路上各個元件的耗時，精算首位元組音訊延遲（TTFAB）的預算上限。
- 描述 TMRoPE 在思考者內部如何跨越視覺、音訊與文字建立絕對時間對齊的位置編碼。
- 掌握即時對話系統的三大交互模式：半雙工（Half-duplex）、輪流交替（Turn-taking）與全雙工（Full-duplex）。

## The Problem｜問題

一個真正的即時語音智慧助理，必須在極短的瞬間精準完成一連串繁重任務：

1. 聆聽使用者發言。執行即時語音 Token 化，並搭配語音活動偵測（VAD）以精確捕捉使用者何時說完一句話。
2. 同步觀察環境（選用）。攝影機以每秒 2 到 4 幀的速度連續擷取影像，與音訊串流並行餵入思考者。
3. 思考決策。基於當前輸入與長程歷史對話紀錄，構思出最合理得體的回應內容。
4. 開口說話。即時合成離散語音 token，解碼為連續類比波形，毫秒級串流傳輸至使用者的耳機揚聲器。

全鏈路上的每一個步驟都在累積延遲。若要具備「自然交談感」，端到端往返總延遲必須死死壓在 500 毫秒以內——低於此門檻，人類大腦便幾乎感受不到卡頓停頓。GPT-4o 宣稱約 250 毫秒；Moshi 突破至 160 毫秒；Qwen2.5-Omni 則落在 350 至 500 毫秒區間。

鏈路上的每一個元件都必須原生支援串流傳輸。任何「先把全部資料批次運算完畢再開始解碼」的架構，在即時對話中皆是死路一條。

## The Concept｜核心概念

### 思考者與發言者（Thinker and Talker）

Qwen2.5-Omni 的經典模組化解耦架構：

- 思考者（Thinker）：一個 7B 至 80B 參數量級的文字生成 Transformer。負責接收交錯輸入的文字、影像與音訊 token，自回歸輸出代表「該說什麼話」的文字 token。
- 發言者（Talker）：一個輕量級的專屬語音生成 Transformer（約 2 億至 10 億參數）。負責即時接收思考者吐出的文字 token 以及最近的發音上下文，自回歸輸出離散語音 token（殘差 VQ 索引）。
- 語音解碼器（Speech decoder）：串流波形神經解碼器（SNAC、MoVQGAN 家族），將離散語音 token 即時還原為物理音訊取樣波形。

這種架構拆分極具工程智慧。思考者必須足夠龐大，才能確保深邃的邏輯思考與事實準確；而發言者則應盡可能小巧輕盈，因為它的工作純粹是局部性的——將確定性的文字翻譯為語音 token。將發言者做大並不會提升表達力，只會白白拖慢首字發音速度。

雙大腦平行串流運作節奏：

1. 思考者吐出文字 token t_i。
2. 發言者（透過串流傳輸）立刻捕獲 t_i，並迅速輸出對應的語音 token s_i, s_{i+1}, ..., s_{i+k}。
3. 語音解碼器邊接收語音 token，邊即時吐出音訊波形。
4. 當思考者推進到文字 token t_{i+3} 時，發言者早已將 t_0 到 t_{i+2} 的聲音串流至使用者耳中！

### TMRoPE——時間對齊的多模態空間位置

思考者必須在單一序列中深度整合影像影格（例如以 4 FPS 抵達）、音訊影格（以每秒 50 幀抵達）以及來自使用者的對話歷史文字。若採用幼稚的先後排布（把所有圖片擺在前面，音訊緊隨其後，最後放文字），時序同步性將蕩然無存。

TMRoPE 為每一個進來的 token 分配實體世界的「絕對時間戳記」。視覺 token 落在 t=2.3 秒；音訊 token 落在 t=2.32 秒；使用者喊出「停止」的文字 token 落在 t=2.35 秒。RoPE 依時間戳記旋轉注意力；在模型的注意力視野中，它們在時間維度上是精確並行發生的。

這正是「他在說你好時同時揮了揮手」能夠被模型自然辨識的底層基礎設施——模型在同一個概念瞬間，看見了動作畫面並聽見了招呼聲。

### 串流語音合成機制

語音 token 必須實現無縫串流。Mini-Omni（Xie & Wu，2024）開創了「語言模型在串流思考的同時邊聽邊說」的新範式：思考者輸出 token 與發言者輸出 token 在同一個序列中交錯前進。只要思考者確認了下一個文字 token，發言者便立刻啟動，完全抹去批次邊界。

Moshi（Défossez 等人，2024 年 10 月）是目前速度最快的開源標竿，在單張 A100 上達成了 160 毫秒的極致 TTFAB。其架構為：單一 7B Transformer 在相鄰位置交替輸出文字與語音 token，並設計了一套「內心獨白（inner monologue）」機制將思考串流與發聲串流解耦。這本質上是在單一模型內部，透過極致訓練將思考者與發言者完美融為一體。

### VAD 語音活動偵測與輪流發言機制

語音活動偵測（VAD）部署在輸入最前端。支援兩種交互模式：

- 半雙工（Half-duplex）：使用者說話時模型專心聆聽；模型說話時使用者專心聆聽。透過 VAD 偵測靜音間隙（通常設定為約 200 毫秒）來判定發言結束並平滑交接話語權。
- 全雙工（Full-duplex）：雙方允許隨時同時開口說話。模型能夠在使用者發言時即時給出「嗯哼」、「對」等打岔反饋（Backchannel），亦能在使用者突然插話時立刻停止發聲。工程難度極高，Moshi 原生支援此能力。

Qwen2.5-Omni 預設採用半雙工輪流交替模式；全雙工能力則需在應用調度層進行深度封裝支援。

### Qwen3-Omni（2025 年 11 月）

全新的後續演進版本：換裝 800 億參數的 Qwen3-80B 作為思考者大腦、擴展發言者容量，並升級了 TMRoPE-v2。端到端延遲逼近 GPT-4o 的 250 毫秒極限，全面開源權重。在 OmniBench 全模態基準測試上，其綜合競爭力直接比肩 Gemini 2.0 Live。

### 正式環境推論延遲預算剖析

針對典型串流語音互動鏈路進行毫秒級拆解：

- 麥克風採集至輸出音訊 Token：約 40 至 80 毫秒。
- 思考者 Prompt 預填充（歷史上下文 + 最新音訊）：7B 模型約 100 至 200 毫秒；70B 模型則需數倍耗時。
- 思考者吐出第一個文字 Token：約 40 毫秒。
- 發言者處理第一個文字 Token：約 20 毫秒。
- 吐出第一組語音 Token：約 40 毫秒。
- 殘差 VQ 解碼：約 30 毫秒。
- 類比語音波形神經解碼：約 50 至 80 毫秒。

端到端首位元組音訊延遲（TTFAB）：7B 規模下約為 320 至 510 毫秒；而在 70B 規模下則落在 600 至 900 毫秒。追求極致品質往往需要 70B+ 大腦，這正是當前開源體系在延遲與智商之間必須權衡的現實鴻溝。

### Token 生成速率數學公式

在 16kHz 取樣率且基礎語音 token 頻率為 50 Hz 的標準下，每秒音訊輸出需要消耗 50 個語音 token。這意味著發言者的 token 生成速率必須嚴格 ≥ 50 tok/s，否則音訊串流將會發生致命卡頓。在 H100 GPU 上，一般大模型推論吞吐約為 30 到 80 tok/s，小巧輕盈的專屬發言者（2 億至 3 億參數）能輕鬆達成此速率；而若強行讓 7B 模型自己一邊思考一邊吐語音 token，生成速度很容易落後於物理播放節奏。

這正是「專屬輕量化發言者」之所以成為工業界標準架構的最核心原因。

## Use It｜實際應用

`code/main.py` 完整實作了：

- 模擬「思考者—發言者」雙大腦串流推論管線，並內建真實的 token 產出速率模擬。
- 支援自由調整模型規模與麥克風取樣率，精算端到端首位元組音訊延遲（TTFAB）。
- 實作基於 VAD 靜音門檻的半雙工輪流交替對話狀態機。

## Ship It｜交付成果

本課產出 `outputs/skill-omni-streaming-budget.md`。給定即時語音產品的目標 TTFAB 門檻與功能需求（是否支援視訊輸入、雙語交互、全雙工插話），它能精確推薦選用 Qwen2.5-Omni、Qwen3-Omni、Moshi 還是 Mini-Omni，並給出思考者與發言者的最佳參數量配比。

## Exercises｜練習

1. 假設產品要求的目標 TTFAB 嚴格為 300 毫秒。在 7B 思考者搭配 300M 發言者的架構下，請詳盡撰寫全鏈路每個元件的耗時預算表。

2. Qwen2.5-Omni 採用 TMRoPE。當使用者在 t=1.0 秒開始開口說話、攝影機在 t=1.2 秒捕捉到手勢動作時，描述模型內部看見的空間時間座標幾何特徵。

3. 全雙工對話要求模型在聆聽使用者說話的同時，能夠主動發聲給出反饋。請設計一份能夠訓練模型學會此行為的訓練資料排版格式。

4. 閱讀 Moshi 論文第 4 節。深入說明其「內心獨白（inner monologue）」機制的運作方式，並解釋為何它能夠在單一模型內部避免顯式拆分思考者與發言者。

5. 吞吐預算計算：若語音標準為 16kHz 取樣率、每秒需 50 個基礎層 token，發言者的生成吞吐必須達到何種門檻才能完全避免音訊播放斷流？

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| Thinker | 「思考大腦」 | 負責高階推理的大型 Transformer，負責產出代表回應內容的文字 token |
| Talker | 「發言嘴巴」 | 負責即時將思考者的文字輸出即時轉譯為離散語音 token 的專屬輕量 Transformer |
| TTFAB | 「首位元組音訊延遲」 | 從使用者說話結束到耳機聽見第一個音訊封包的端到端時間；<500ms 具備真實交談感 |
| TMRoPE | 「時間對齊多模態 RoPE」 | 跨越視覺、音訊與文字，利用實體絕對時間戳記實現時序對齊的旋轉位置編碼 |
| Half-duplex | 「半雙工輪流交替」 | 使用者與模型輪流開口；藉由前端 VAD 靜音間隙偵測話語權交接 |
| Full-duplex | 「全雙工即時雙向」 | 雙方允許隨時同時開口發聲；模型具備即時打岔與邊聽邊反饋的高階能力 |
| Inner monologue | 「內心獨白機制」 | Moshi 採用的單模型設計，將內部思考串流與外部發音串流在序列中交錯排布 |
