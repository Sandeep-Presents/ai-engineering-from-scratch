# MIO 與任意對任意串流多模態模型（MIO and Any-to-Any Streaming Multimodal Models）

> GPT-4o 實現了一款多數開源模型望塵莫及的旗艦產品：一個能夠即時聽見聲音、看見動態視訊並以自然語音流暢對話的智慧代理。到了 2024 年底，開源生態給出的最強正面回應正是 MIO（Wang 等人，2024 年 9 月）構想。MIO 將文字、影像、語音與音樂全數離散 Token 化，在交錯排列的序列上訓練單一因果 Transformer，達成了真正的任意模態對任意模態（Any-to-Any）全向生成。AnyGPT（Zhan 等人，2024 年 2 月）是其概念驗證原型；MIO 則是其工業級擴展版本；Unified-IO 2（Allen AI，2023 年 12 月）則是融入視覺定位與實體動作執行的堂兄弟。本課深入解構「四套 Tokenizer、單一 Transformer、支援極速串流解碼」的任意對任意大一統工程架構。

**Type:** Learn
**Languages:** Python (stdlib, four-modality token allocator + streaming decode loop)
**Prerequisites:** Phase 12 · 11 (Chameleon), Phase 6 (Speech and Audio)
**Time:** ~120 minutes

## Learning Objectives｜學習目標

- 設計一套能夠同時容納文字、影像、語音與音樂 token 且保證完全零碰撞的超大共用詞彙表。
- 深入對比 SEED-Tokenizer（影像端）與 SpeechTokenizer 殘差 VQ（語音端）在壓縮比率與還原保真度上的工程權衡。
- 剖析建構全功能任意對任意生成能力的四階段漸進式訓練課綱。
- 掌握當前開源領域三大任意對任意模型配方及其核心取捨：MIO、AnyGPT 與 Unified-IO 2。

## The Problem｜問題

打造一個大一統多模態模型是人人的夢想，但要在工程規模上真正跑通卻無比艱難。在 2024 年之前，絕大多數聲稱支援「全模態」的系統本質上全是串接的流水線管線：視覺模型 → 文字轉譯 → 語音模型 → 音訊輸出。每一個跳轉環節都會遺失豐富語境、堆疊額外延遲，並使系統訓練變得混亂無比。GPT-4o 展示的則是真正亞秒級即時互動的單模型大一統架構；開源體系足足落後了數月之久。

其核心工程挑戰包含：

- 必須為每個模態打造專屬的高品質 Tokenizer，且在保證足夠還原精度的同時，將 token 產出速率壓制在 Transformer 能夠消化的頻率範圍內。
- 單一詞彙表必須同時為文字（3.2 萬+）、影像（1.6 萬+）、語音（4000+）以及音樂（8000+）劃分互不衝突的 ID 區間，全域字典容量至少需要 48,000 以上。
- 訓練資料必須全面覆蓋所有可能的輸入—輸出模態排列組合（文生圖、圖生音、音生圖等），或賦予模型強大的泛化組合能力。
- 推論生成必須原生支援高速串流輸出，才能滿足真實人類語音互動的苛刻即時延遲要求（首字元音訊延遲必須低於 500 毫秒）。

## The Concept｜核心概念

### 四大模態的四套 Tokenizer

MIO 建構的 Tokenizer 武器庫如下：

- 文字端：標準 BPE tokenizer，詞彙量約 32,000。
- 影像端：SEED-Tokenizer（2023）——包含 4096 個碼本向量的離散量化 VAE，每張影像切分為 32×32 個 token。
- 語音端：SpeechTokenizer 殘差 VQ（Residual-VQ，2023）——將 16kHz 原始波形編碼為 8 層階層式碼本；第 1 層專注於粗粒度文字內容，後續層級則逐步補充語調、情感與說話者音色特徵。
- 音樂端：基於相似的階層式殘差 VQ（源自 Meta 的 MusicGen / Encodec 家族），配備 4 到 8 層碼本。

每個模態皆輸出標準的離散整數 token。在全域共用詞彙表中，為它們劃分彼此完全隔離的獨立 ID 區間：

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

全域詞彙表總計約 4.8 萬維度。底層的輸入 embedding 矩陣與頂層的線性輸出投影層，全量覆蓋這整個跨模態整數空間。

### 串流解碼機制

語音生成高度依賴殘差向量量化（Residual-VQ）。Transformer 本體僅負責自回歸預測最底層的基礎語音 token（第 0 層）；隨後透過一個高度平行的殘差解碼器，同步預測後續所有補充層級的特徵。在 16kHz 取樣率下，每一個第 0 層 token 大約對應 50 毫秒的實體音訊時長。

即時串流運作節奏：

1. 使用者對著麥克風說話；即時音訊 Tokenizer 每隔 50 毫秒吐出相應的語音 token。
2. MIO 即時吞吐這些 token（包含 prompt 預填充與增量前向傳播）。
3. 輸出端的語音 token 隨生成過程即時向外串流；後端的平行語音解碼器僅需約 50 到 150 毫秒的延遲，便能將 token 即時彩現為類比音訊訊號。
4. 首位元組音訊延遲（Time-to-First-Audio-Byte, TTFAB）：在 MIO 實測中壓制在 300 至 500 毫秒之間，極度逼近了 GPT-4o 宣稱的約 250 毫秒極限。

Mini-Omni（arXiv:2408.16725）、GLM-4-Voice（arXiv:2412.02612）以及 Moshi（arXiv:2410.00037）皆屬同期的前沿串流語音大模型。尤其是 Moshi，在單卡 GPU 上達成了驚人的 160 毫秒端到端雙向往返延遲。

### 四階段訓練課綱

MIO 規劃了縝密的四階段漸進式訓練流程：

1. 第 1 階段——特徵對齊（Alignment）：在海量跨模態對齊語料庫上訓練（圖文對、音文對、樂文對）。各對齊任務僅調用自身專屬的詞彙區間，主要目的在於奠定共用詞彙表的穩定 embedding 空間。
2. 第 2 階段——交錯混合（Interleaved）：引入豐富的多模態交錯文件（帶有插圖與視訊的部落格、附帶文字轉錄的 Podcast 播客等），深度培養跨模態上下文理解與跳轉能力。
3. 第 3 階段——語音特化增強（Speech-enhanced）：額外注入大規模音訊資料，專項拔高語音生成的自然度與表現力，且確保純文字推理能力不發生滑坡。
4. 第 4 階段——指令調校（SFT）：在全模態指令資料集上展開全面訓練，包含 VQA 問答、詳細敘事描述、跨模態摘要以及全雙工語音對話。

跳過任何一個階段皆會引發特定模態的崩潰：跳過第 2 階段會喪失跨模態聯想力；跳過第 3 階段則語音聽起來乾癟機械。

### 視覺思維鏈（Chain-of-Visual-Thought）

MIO 開創性地提出了「視覺思維鏈」機制：允許模型主動生成中間狀態的影像 token，作為其複雜推理過程的暫存草稿紙（scratchpad）。例如面對提問「這隻貓是否正在爬樹？」時，模型會：

1. 自發生成一串 `<image>` token，在內部畫布上勾勒出該場景的空間草圖。
2. 生成文字對自己畫出的草圖展開空間幾何分析。
3. 輸出最終確定性的邏輯解答。

這張彩現出的中間影像扮演了輔助記憶體的作用，使模型在複雜空間推理評測上的成績顯著提升。此概念與純文字領域的思維鏈（CoT）異曲同工。

### 任意對任意領域的競爭者體系

- AnyGPT（arXiv:2402.12226）：涵蓋文字、影像、語音、音樂四大模態，是早期探索的關鍵先驅。
- Unified-IO 2（arXiv:2312.17172）：額外整合了機器人實體動作、幾何深度圖與表面法線預測；任務多樣性更高，但參數量較小。
- NExT-GPT（arXiv:2309.05519）：以 LLM 為核心，外部銜接模態特化的擴散解碼器；並非純粹的單模型大一統路線。
- CoDi（arXiv:2305.11846）：基於共享連續潛在空間的可組合擴散模型。

MIO 是目前最貼近「純 Token 自回歸」哲學的任意對任意系統，其思想直接承襲自 AnyGPT。

### 延遲預算剖析

對於一款語音即時互動產品，鏈路上每一個元件的耗時皆生死攸關：

- 麥克風音訊採集至輸出 Token：約 50 毫秒。
- 8B 模型的 Prompt 預填充（歷史上下文 + 最新音訊）：約 100 毫秒。
- 吐出第一個輸出 Token：約 50 毫秒。
- 平行殘差 VQ 解碼至彩現音訊波形：約 100 至 150 毫秒。

端到端首位元組音訊延遲（TTFAB）理論極限約為 300 毫秒。GPT-4o 宣稱約 250 毫秒；Moshi 最佳化至 160 毫秒；MIO 與 AnyGPT 在公開標準測試中則普遍落在 400 至 600 毫秒區間。

### 為何任意對任意依舊極具挑戰

即使到了 2026 年，開源全模態模型在兩大維度上依然落後於閉源旗艦：

- 語音真實感與自然度：殘差 VQ 的量化壓縮依然存在資訊損耗；其合成語音在自然呼吸聲與情感細膩度上，與 ElevenLabs 頂級 TTS 相比依然帶有些許機械味。
- 跨模態深層推理：當要求模型「針對你看到的畫面即興譜寫一段歌曲並唱出來」時，其失敗率依然遠高於單純的純視覺任務。

這些依然是當前最炙手可熱的前沿研究課題。Qwen3-Omni（第 12.20 課）正是 2025 年開源生態在此方向上的巔峰突圍代表。

## Use It｜實際應用

`code/main.py` 完整展示了：

- 宣告四大模態的共用詞彙表區間分配並印出清晰地圖。
- 模擬多模態輸入路由器，將混合文字、影像、語音片段與音樂檔案精準指派至正確的 Tokenizer。
- 模擬文字轉語音的串流解碼流程，並精確統計鏈路上的各段延遲。
- 計算在給定編碼器、預填充與解碼器耗時下的預期首字元音訊延遲（TTFAB）。

## Exercises｜練習

1. 假設你的線上產品接收語音輸入並即時以語音回答。目標端到端延遲門檻為何？請逐一列出消耗時間的四大關鍵架構元件。

2. SpeechTokenizer 採用了 8 層殘差 VQ 碼本。請論證為何對殘差層進行「平行解碼」是絕對必要的（相較於逐層串行預測），這項並行設計能帶來多少延遲節省？

3. 假設你的詞彙表包含 3.2 萬文字 token、4000 影像 token 與 4000 語音 token。現在欲額外加入 8000 個音樂 token 與 10 個模態分隔符號。在隱藏維度為 4096 的設定下，這增加了多少 embedding 矩陣的參數量？

4. 視覺思維鏈（Chain-of-visual-thought）允許模型在回答前提早產出中間影像。哪些特定類型的空間問題能從中獲益？哪些問題反而會因額外的 token 消耗而拖慢回應？

5. 閱讀 Moshi 論文（arXiv:2410.00037）。描述其「內心獨白（inner monologue）」機制的運作方式，並將其與 MIO 的視覺思維鏈進行對照剖析。

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| Any-to-any | 「全模態任意對任意」 | 單一模型在文字、影像、語音與音樂之間，支援任意維度的全雙工輸入與輸出 |
| Residual-VQ | 「殘差語音堆疊碼本」 | 階層式向量量化架構，底層捕捉文字內容，後續層級平行補全音色與語調細節 |
| SEED-Tokenizer | 「影像離散量化編碼器」 | 具備 4096 碼本容量的離散影像量化器，為 MIO 所採用的核心視覺前端 |
| Chain-of-visual-thought | 「視覺草稿思維鏈」 | 模型在產出最終回答之前，自發生成一幅中間影像輔助自身進行空間邏輯推理 |
| Time-to-first-audio-byte | 「首字元音訊延遲」 | 從使用者說話結束到耳機聽見第一個音訊封包的端到端延遲；<500ms 具備真實交談感 |
| Four-stage curriculum | 「全模態漸進訓練法」 | 「模態對齊 → 交錯網頁 → 語音特化 → 全模態指令調校」的嚴謹訓練時程時序 |
