# Show-o 與離散擴散大一統模型（Show-o and Discrete-Diffusion Unified Models）

> Transfusion 選擇了揉合連續向量與離散 token 的複合路線。Show-o（Xie 等人，2024 年 8 月）則走向了另一端：文字 token 遵循因果下一個 token 預測，而影像 token 則採用承襲自 MaskGIT 的遮蓋式離散擴散（Masked Discrete Diffusion）。兩者統一於具備混合注意力遮罩的單一 Transformer 內部。最終成果在單一骨幹網路、每種模態配置單一 Tokenizer、單一損失形式（將下一個 token 預測泛化為遮蓋還原預測）之下，完美統一了視覺問答（VQA）、文字生成圖片（T2I）、局部重繪（Inpainting）以及混合模態生成。本課深度剖析 Show-o 的架構設計——為何遮蓋式離散擴散是一種高平行度、極少步長的高效影像生成機制——並與 Transfusion 及 Emu3 展開對比。

**Type:** Learn
**Languages:** Python (stdlib, masked-discrete-diffusion sampler)
**Prerequisites:** Phase 12 · 13 (Transfusion)
**Time:** ~120 minutes

## Learning Objectives｜學習目標

- 解釋遮蓋式離散擴散的核心原理：均勻遮蓋 token 並引導 Transformer 逐步還原預測的排程機制。
- 在推論速度與成圖品質兩大維度上，深入對比平行影像解碼（Show-o、MaskGIT）與逐 token 自回歸解碼（Chameleon、Emu3）。
- 掌握單一 Show-o 模型檢查點所同時原生支援的三大核心任務：文字生成圖片（T2I）、視覺問答（VQA）以及影像局部重繪（Inpainting）。
- 依據業務情境挑選合適的遮蓋排程曲線（餘弦、線性、截斷式），並論證其對取樣生成品質的深遠影響。

## The Problem｜問題

Transfusion 的雙損失訓練雖然行得通，但在訓練動態上充滿挑戰——連續擴散損失與離散 NTP 交叉熵損失處於截然不同的數值量級，平衡兩者的權重係數本質上是一個昂貴的高維超參數搜尋過程。架構雖強大，但工程實作極其繁複。

Show-o 給出的另闢蹊徑解答是：讓兩種模態皆維持純粹的離散狀態（類似 Chameleon），但在影像生成時改採遮蓋式離散擴散來實現「高度平行化生成」，徹底告別緩慢的逐 token 自回歸。如此一來，整體訓練目標便自然收斂為單一的「遮蓋 token 預測損失」，將「下一個 token 預測」無縫包含為其特殊特例。

## The Concept｜核心概念

### 遮蓋式離散擴散（MaskGIT）

Chang 等人（2022）發表的 MaskGIT 機制非常精妙。生成流程從一張全遮蓋的影像開始（每個 patch 位置皆填入特殊的 `<MASK>` token ID）。在每一個生成步長中，Transformer 同時且平行預測所有當前被遮蓋的 token；隨後僅保留預測置信度最高的 Top-K 個 token 並將其鎖定，其餘未達標的位置則重新施加遮蓋。歷經約 8 到 16 次迭代後，所有位置皆被高置信度的像素索引填滿。每一步該解除多少比例的遮蓋，取決於精心調校的排程——實證表明餘弦排程（Cosine Schedule）表現最佳。

其訓練流程極度簡潔：從區間 [0, 1] 中均勻隨機取樣一個遮蓋比例，將其套用於影像的 VQ 離散 token 序列中，並訓練 Transformer 準確預測被遮蓋的原始 token。這正是 BERT 在文字領域採用的經典遮蓋語言建模，被極為巧妙地擴展至多模態影像生成領域。

### Show-o：單一 Transformer，混合注意力遮罩

Show-o 將 MaskGIT 的機制完全融入了因果語言模型 Transformer 之中。其混合注意力遮罩規則如下：

- 文字 token：維持嚴格的單向因果遮罩（標準 LLM 設定）。
- 影像 token：在同一個影像區塊內部開放全域雙向注意力（確保被遮蓋的 token 在預測時能自由凝視同一影像中的所有已知上下文）。
- 圖文交互：文字可以凝視先前出現的影像，影像生成亦能凝視先前的文字 prompt。

訓練資料在三大形態間動態交替：
1. 純文字序列上的標準因果 NTP 訓練。
2. 文生圖（T2I）樣本：文字 → 帶有遮蓋的影像 token，計算遮蓋 token 預測損失。
3. 視覺問答（VQA）樣本：影像 → 文字，以文字端的遮蓋預測為主（本質上即為標準 NTP）。

全系統的統一損失即為作用在 `<MASK>` 位置上的交叉熵：當只有最後一個 token 被遮蓋時，它退化為純文字 NTP；當隨機子集被遮蓋時，它演變為影像離散擴散。

### 高度平行的取樣機制

Show-o 僅需約 16 個步長即可生成一張完整影像，遠勝自回歸模型動輒需要約 1000 次前向傳播（逐 token 吐出）的漫長等待，且能與連續擴散模型的約 20 步相抗衡。在每一步中，模型平行預測所有遮蓋位置，鎖定最高置信度的 Top-K 個預測，隨後重複迭代。

全方位速度對比：
- Chameleon / Emu3（逐 token 自回歸）：需要 N_tokens 次 Transformer 前向傳播，每張圖通常高達 1024 到 4096 次。
- Transfusion（連續流匹配擴散）：約 20 次步長，每次皆需執行一次完整的 Transformer 前向傳播。
- Show-o（遮蓋式離散擴散）：約 16 次步長，每次執行一次完整的 Transformer 前向傳播。

在同等模型規模下，Show-o 的生成速度遠快於 Chameleon；而在步長數量上逼近 Transfusion 的同時，其每步計算開銷更為低廉（僅需在離散詞彙表上預測 logit，無需計算連續的 MSE 擴散去噪）。

### 單一權重檢查點涵蓋的多元任務

Show-o 在推論時支援四大核心任務，完全由輸入 prompt 格式自發觸發：

- 純文字生成：標準因果自回歸文字續寫。
- 視覺問答（VQA）：輸入影像，自回歸輸出文字解答。
- 文字生成圖片（T2I）：輸入文字描述，透過遮蓋式離散擴散平行生成影像 token。
- 局部重繪（Inpainting）：傳入部分 token 被遮蓋的殘缺影像，由模型自動補全缺失區域。

其強大的局部重繪能力完全是遮蓋式預訓練帶來的免費副產物。只需將 VQ token 網格中的特定區域予以遮蓋，輸入文字引導 prompt，模型便能自然填補這些空白。

### 遮蓋排程策略

在推論迭代中，逐步解除遮蓋的節奏直接決定了生成品質。Show-o 推薦採用餘弦排程曲線：

```
mask_ratio(t) = cos(pi * t / (2 * T))   # t = 0..T
```

在第 0 步時，所有 token 皆處於遮蓋狀態（比例 1.0）；在第 T 步時，全數遮蓋皆被解除。餘弦函數將主要的權重密度集中在中段區間，此時已解鎖足夠的輪廓資訊，模型進行細部預測最具資訊量。線性排程雖亦能運作，但生成品質衰減較快。

### Show-o2

2025 年發布的升級版 Show-o2（arXiv:2506.15564）全面擴展了此架構：換裝更強大的語言模型底座、升級更高重建上限的 Tokenizer，並最佳化了遮蓋排程演算法。核心架構形態維持一致。

### Show-o 在技術光譜中的座標

在 2026 年的前沿多模態版圖中：

- 離散 Token + NTP 自回歸：Chameleon、Emu3。架構極簡純粹，但推論生成速度緩慢。
- 離散 Token + 遮蓋式離散擴散：Show-o、MaskGIT、LlamaGen、Muse。高度平行取樣，但上限受限於離散 Tokenizer 的重建極限。
- 連續表徵 + 擴散去噪：Transfusion、MMDiT、DiT。成圖逼真度最高，但訓練排程與雙損失調控較繁複。
- 連續表徵 + 流匹配 VLM：JanusFlow、InternVL-U。最新前沿探索。

選型指南：若需要在單一開源模型中同時通吃文生圖、影像局部重繪與視覺問答，且注重快速推論吞吐，選 Show-o；若對成圖逼真度有極致苛求，且具備調控雙損失的深厚工程實力，選 Transfusion。

## Use It｜實際應用

`code/main.py` 完整模擬了 Show-o 的平行解碼取樣流程：

- 宣告一個包含 16 個 VQ token 的玩具網格。
- 模擬一個根據文字 prompt 與當前已知 token 預測 logit 的抽象 Transformer。
- 依據餘弦排程在 8 個步長內執行平行的遮蓋解鎖取樣。
- 逐步印出中間狀態的遮罩幾何演進與最終產出的 token 分布。

實際動手運行，親眼見證遮罩如何由模糊的空白一步步凝聚為清晰的語意實體。

## Ship It｜交付成果

本課產出 `outputs/skill-unified-gen-model-picker.md`。當產品同時需要視覺感知理解（VQA、圖片說明）與視覺生成（T2I、影像局部修復）且限定採用開源權重時，它能客觀對比 Show-o 體系、Transfusion/MMDiT 體系與 Emu3/Chameleon 體系，並給出具體的工程取捨分析與決策推薦。

## Exercises｜練習

1. 遮蓋式離散擴散通常在約 16 步內完成取樣。為何不能縮減為 1 步？若在第 0 步就強行平行預測並解鎖全數 token，畫面會發生何種災難性崩潰？

2. 局部重繪是遮蓋擴散天然具備的能力。請提出一個真實或假想的產品落地場景，論證為何 Show-o 的內建重繪能力遠勝於專門的獨立特化模型。

3. 餘弦排程 vs 線性排程：在總步長 T=8 的設定下，精確計算出每一步解鎖的 token 比例數值。哪一種曲線在資訊量增長上更為平滑均衡？

4. 一張 512×512 的 Show-o 影像包含 1024 個 token。在碼本容量 K=16384 下，模型輸出的資訊量為 1024 × log2(16384) = 14,336 個位元（約 1.75 KiB）。而 Stable Diffusion 輸出的原始像素為 512×512×24 個位元 = 6,291,456 個位元（約 768 KiB）。其壓縮比為何？這筆巨大的壓縮率換來了何種生成代價？

5. 閱讀 LlamaGen 論文（arXiv:2406.06525）。深入分析 LlamaGen 的類別條件自回歸影像生成模型，與 Show-o 的遮蓋式離散擴散在解碼機理上有何本質差異？

## Key Terms｜關鍵術語

| 術語 | 常見俗稱 | 實際意義 |
|------|-----------------|------------------------|
| Masked discrete diffusion | 「遮蓋式離散擴散」 | 訓練模型預測被隨機遮蓋的離散 token；推論時以多輪迭代平行解鎖置信度最高的預測 |
| Cosine schedule | 「餘弦解鎖排程」 | 遮蓋比例隨時間步呈餘弦曲線衰減；使置信度的增長集中在中段最具資訊量的區間 |
| Parallel decoding | 「全序列平行解碼」 | 每一步皆在單次前向中平行預測全數遮蓋 token，隨後鎖定 Top-K 個高置信度結果 |
| Hybrid attention | 「因果加雙向混合遮罩」 | 對文字序列維持因果因果遮罩，但在影像內部開放全域雙向注意力的專屬遮罩架構 |
| Inpainting | 「畫面局部重繪修復」 | 給定部分 token 被遮蓋的殘缺影像，由模型自主預測補齊；為遮蓋訓練目標的天然副產物 |
| Commitment rate | 「每步鎖定 Top-K」 | 每一輪迭代中被正式確認鎖定的 token 數量；負責調控推論步長與生成品質的取捨 |
