# 管線並行與氣泡率分析（Pipeline Parallel and Bubble Analysis）

> 張量並行（Tensor Parallel）是將單個矩陣乘法跨卡切分。而管線並行（Pipeline Parallel）則是將模型沿著深度方向跨節點切分，每個節點各自執掌一個流水階段（Stage）。微批次（Microbatches）在管線中順次流動。啟動時與收尾時各階段被迫陷入的空閒等待時間，就是所謂的**管線氣泡（Pipeline Bubble）**；而將氣泡率壓縮至極限，正是管線並行的全部工程精髓所在。

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 19 Track C lessons 42-49
**Time:** ~90 min

## Learning Objectives｜學習目標

- 將序列化模型切分為 N 個階段（Stages），並在 N 個 Rank 節點之間模擬前向管線傳遞。
- 使用經典的 GPipe 排程策略（全量前向填充，隨後逆向反向排空）調度 M 個微批次，並推導計算理論氣泡率（Bubble Fraction）。
- 對比 GPipe 與 Megatron-LM、PipeDream 所廣泛採用的交織 1F1B（One-Forward-One-Backward）排程架構。
- 深入捍衛階段劃分準則：各階段**算力均等（Equal Compute）**的重要性遠遠超越**參數量均等（Equal Parameters）**。

## The Problem｜問題

一個在 FP16 精度下運作的 700 億參數（70B）大模型，單是模型權重本身就需要吞噬高達 140 GB 的記憶體。任何單張消費級顯卡皆絕對無從承受。ZeRO-3 雖然能將參數分片分散至各卡，但在每一步前向計算時依然需要所有節點透過 AllGather 跨網路拉取完整層參數，在每一層皆要承擔 log(N) 跳的通訊延遲。管線並行（Pipeline Parallel）另闢蹊徑：將模型沿著深度水平切成 N 個階段，每個 Rank 節點僅持有其中一個階段。第 1 層的前向傳播在 Rank 0 上計算完畢後，直接將活化值（Activations）張量透過網路交接給 Rank 1；Rank 1 運行第 2 層並交接給 Rank 2，依此類推。反向傳播則沿著完全相反的逆向通道回傳。記憶體佔用呈現線性下降，因為每個節點僅需常駐單一階段的層結構；但其運算呈現序列化依賴，這便引發了致命的**氣泡率難題（The Bubble Problem）**。

所謂管線氣泡，是指在管線剛啟動時（前續節點在計算、後續節點在眼巴巴乾等第一個微批次送達）以及收尾時（前續節點已經收工、在乾等最後一個微批次的反向梯度排空）所產生的不可避免的實體硬體閒置時間。在包含 M 個微批次與 N 個階段的系統中，單階段的氣泡佔比公式精確為：(N-1)/(M + N - 1)。當 M=8、N=4 時，氣泡率高達 27%（超過四分之一的算力被白白浪費！）；而當 M=64、N=4 時，氣泡率被迅速稀釋壓制在 4.5%。微批次數量 M 越大，氣泡率越小；但這意味著單個微批次的批次大小必須足夠精巧，這正是驅動微批次極限架構設計的核心約束。

### GPipe 排程策略

在啟動任何反向傳播之前，優先用全部 M 個微批次將前向管線徹底填滿；隨後依序執行反向傳播進行排空。每個微批次在前向傳播中產生的活化值必須在記憶體中持續保留，直到其對應的反向傳播結束為止，因此記憶體開銷隨微批次數量 M 呈線性增加。前向傳播耗費 M + N - 1 個時鐘週期，反向傳播同樣耗費 M + N - 1 個週期。每個階段產生的有效計算為 2M 個週期，氣泡浪費為 2(N-1) 個週期。在單個前向與反向耗時均等的前提下，氣泡率精確收斂為 (N-1)/(M + N - 1)。確保 M >> N 是消解 GPipe 氣泡率的唯一正解。

### 1F1B 交織排程策略（One-Forward-One-Backward）

交織推進：每當某個微批次的前向傳播抵達最後一個階段時，該階段立即啟動其對應的反向傳播並向回串流輸送。整個排程在每個階段交替執行「一次前向、一次反向」。氣泡仍為 N−1 個步驟，但其最大活化值記憶體佔用受限在管線深度 N 範圍內，完全與微批次總量 M 解耦無關！工業級生產框架（Megatron-LM、PipeDream）全體統一採用 1F1B。本課首先完整實作結構更為純粹的 GPipe，並在擴充練習中引導你實作 1F1B。

### 為何階段間必須追求「算力均等」，而非「參數均等」

若階段 0 前向計算耗時 50 毫秒，而階段 1 耗時 100 毫秒，那麼在每一個週期中，所有其餘節點皆被迫停工 50 毫秒在原地苦苦等待階段 1 釋放資源！以參數量均等來劃分階段是嚴重的外行失誤：在 Transformer 大模型中，運算開銷（FLOPs）主要集中在中間各層的注意力矩陣點積與 MLP 矩陣乘法上；而最底層的 Embedding 查表矩陣雖然參數量龐大，但其運算開銷卻微乎其微。階段切分必須追求**各階段浮點運算量（FLOPs）絕對均等**，而非權重張量體積均等。

### 微批次 vs 全局批次

管線同時調度 M 個微批次，每個微批次大小為 B。有效全局批次大小精確等於 M*B。單次管線步進結束時累計的梯度，就是這 M*B 個樣本上的全局總梯度。氣泡率取決於 M；最佳化器感知到的是 M*B。調校 M 意味著在「氣泡率」（M 越大氣泡越小）與「活化值記憶體開銷」（在 GPipe 中 M 越大，記憶體開銷越高）之間進行生死博弈。

## Build It｜動手實作

`code/main.py` 實作了以下核心模組：

- `PipelineStage`：小巧的 `nn.Module`，持有單一階段的參數層，對外暴露 `forward(activation)` 介面。
- `Pipeline(stages, num_microbatches)`：在模擬階段上，依據各階段設定的模擬物理耗時，調度 GPipe 全套前向填充與反向排空排程。
- `bubble_fraction(num_stages, num_microbatches)`：閉式解析計算公式 (N-1)/(M + N - 1)。
- 4 階段端到端演示：打印逐個微批次的甘特圖時序追蹤，並呈報實測氣泡率與理論公式的對比驗收。

執行測試：

```bash
python3 code/main.py
```

輸出結果：展示一張以階段為行、微批次時序為列的甘特圖（Gantt Chart），並嚴密校驗實測氣泡佔比與理論預測值在誤差範圍內精確吻合。

## 工業級正式環境落地模式

三大實戰工程技巧，能讓管線並行架構足以支撐線上千億模型預訓練：

**活化值檢查點（Activation Checkpointing）與管線並行是天作之合**：在 GPipe 排程中，在途的 M 個微批次會導致活化值記憶體開銷增加至 M 倍。活化值檢查點在反向傳播時重新計算前向結果，以微弱的算力代價換取巨大的記憶體釋放；兩者的結合，是讓管線並行能夠在超長上下文序列上平穩落地的核心法寶。

**階段負載均衡必須依託真實測量，絕非主觀假設**：工業級團隊會在目標硬體加速卡上預先運作 Profiler，實測每層神經網路的真實 FLOPs 與物理時鐘耗時，隨後以此為依據對層結構進行非對稱切割。Megatron-LM 的 `--num-layers-per-stage` 參數支援傳入一個自定義列表，允許為不同階段分配不同數量的層，以完美抹平頭尾特殊層帶來的負載偏差。

**Send-Recv 通訊排程必須堅決杜絕死鎖**：若所有階段同時先發送後接收，整個網路鏈路將當場陷入分散式死鎖！業界標準解法是實施奇偶交織排程：偶數 Rank 節點先發送後接收，奇數 Rank 節點先接收後發送。本課程式碼顯式模擬了該交織時序。

## Use It｜實際應用

工業級生產框架在底層全體遵循完全相同的架構：

- **Megatron-LM**：大規模管線並行的業界標竿。全面採用 1F1B 排程，並支援張量並行（TP）+ 管線並行（PP）+ 資料平行（DP）三維混合編織（3D Parallelism）。
- **DeepSpeed Pipeline**：與 ZeRO 深度整合；ZeRO-1 搭配管線並行是大型開放模型常見的組合。
- **PyTorch Pipe**：PyTorch 官方原生內建的管線封裝器，依託 `torch.distributed.pipeline.sync.Pipe` 實作。

## Exercises｜練習

1. 實作 1F1B 交織排程策略，嚴格驗證其氣泡率與 GPipe 完全一致，但其峰值活化值記憶體佔用被成功限制在固定常數範圍內。
2. 在更深層的神經網路上實測各階段的真實物理耗時，並依據實測毫秒數重新動態平衡各階段所分配的層數。
3. 為管線微批次引入跨步梯度累加（Gradient Accumulation），驗證累計後的總梯度與單次全量大批次前向傳播產出的梯度完全等價。
4. 將管線並行與活化值檢查點（Activation Checkpointing）結合，實測記憶體佔用的下降幅度與計算時間增幅的比例。
5. 將管線並行與 DDP 資料平行相結合（即管線中的每個 Rank 本身被複製為一個資料平行組），深入推導該二維混合並行網格的時序排程圖譜。

## Key Terms｜關鍵術語

| 術語 | 常見說法 | 實際含義 |
|---|---|---|
| Pipeline parallel（管線並行） | 「沿模型深度進行模型平行」 | 沿著模型深度方向將模型切分為多個階段，每個 Rank 持有一個階段，活化值沿著鏈路順序傳遞 |
| Bubble（管線氣泡） | 「管線閒置時間」 | 由於前向依賴與反向等待，導致某些計算節點被迫陷入完全閒置的無效等待時間 |
| Microbatch（微批次） | 「批次切片」 | 管線中流動的最小獨立前向與反向運算單元；微批次數量 M 越大，全局氣泡率越低 |
| GPipe | 「先填滿再排空」 | 先將所有 M 個微批次的前向傳播全部填滿、隨後依序執行反向排空的排程模式；活化值記憶體開銷較高 |
| 1F1B | 「交錯排程」 | 一次前向緊跟一次反向的交織排程模式；將活化值記憶體開銷嚴格限制在管線深度之內 |
