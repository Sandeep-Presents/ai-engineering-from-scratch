# 生成式 Agent 與湧現式社會模擬（Generative Agents and Emergent Simulation）

> Park 等人於 2023 年（UIST '23，arXiv:2304.03442）在名為 **Smallville** 的沙盒中部署了 25 個 Agent，採用三部分架構：**記憶流（Memory stream）**（自然語言事件日誌）、**反思（Reflection）**（Agent 針對自身記憶流生成的高階綜合認知）以及**規劃（Plan）**（先規劃一天，再細分為子計畫）。研究的里程碑成果是「情人節派對」的湧現：只對單一 Agent 植入「想舉辦情人節派對」的種子，沒有額外腳本，邀請便在群體中擴散、各 Agent 協調日期，最後派對舉行；其他 24 個 Agent 起初並不知道這場派對。消融實驗顯示三個元件對擬真度缺一不可。文獻記錄的失效主要是空間社會常規錯誤（闖入已關門的店、多人擠進單人廁所）。這套架構是 2026 年 Agent 模擬與多 Agent 社會行為評估的參考架構。

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 04 (Primitive Model), Phase 16 · 13 (Shared Memory)
**Time:** ~75 minutes

## Problem｜問題

大多數多 Agent 系統都是高度腳本化的團隊：規劃者規劃、工程師寫程式、審查者審查。這對定義明確的任務有效。但當 Agent 擁有記憶、優先順序與開放世界時，它無法捕捉其中自然出現的非腳本化湧現行為。研究、社會模擬，以及越來越多的遊戲 AI，都需要第二類系統。

Smallville 是這類系統的基準架構。在 Park 等人 2023 年的研究之前，最好的 Agent 模擬大多只是淺層的腳本跟隨者；之後，這個模式成為開放世界生成式 Agent 的預設做法。若你在 2026 年打造 Agent 模擬，要麼採用 Smallville 的三個元件，要麼明確說明為何不採用。

## Concept｜核心概念

### 三個核心元件

**記憶流（Memory stream）。** 僅能附加的日誌，記錄觀察、行動、反思與規劃。每筆條目包含時間戳記、類型、自然語言描述，以及衍生的中繼資料：**新鮮度（Recency）**、**重要性（Importance）**（由 Agent 在寫入時自評 1–10）與**相關性（Relevance）**（與當前查詢的餘弦相似度）。

```
[2026-02-14 09:12:03] observation: Isabella Rodriguez asked me if I like jazz
[2026-02-14 09:14:22] reflection:   I enjoy long conversations about music
[2026-02-14 10:05:00] plan:         Attend Isabella's Valentine's Day party tonight
```

記憶檢索結合這三項分數：`score = w_recency * e^(-decay * age) + w_importance * importance + w_relevance * cos_sim`。前 k 筆（Top-k）條目進入當前 prompt。

**反思（Reflection）。** 每隔 N 筆記憶或遇到重要事件時，Agent 會從近期記憶中生成更高階的綜合結論。反思條目會寫回記憶流，並可像其他記憶一樣被檢索。這就是 Agent 形成「理解」的方式，也就是架構中長期信念的對應物。

**規劃（Plan）。** 自頂向下的分解。先以粗略方式擬定一日規劃（「去上班，晚上和 Klaus 吃飯」），再細分為小時規劃，最後是行動層級規劃。規劃可修訂：當新觀察與規劃衝突時，Agent 只重新規劃受影響的段落。

### 為什麼三者都需要（消融實驗）

Park 等人分別移除觀察、反思與規劃進行消融實驗。每一項移除都會降低擬真度：

- 沒有**觀察**：Agent 會遺漏情境，依據過時的信念行動。
- 沒有**反思**：Agent 無法形成高階信念；互動停留在表面。
- 沒有**規劃**：行為變成被動的反應雜訊，目標也會消散。

人類評審在三者齊備時給出的擬真度（Believability）評分最高；拿掉任何一項，都會造成可測量的退步。

### 情人節派對的湧現

其中一個 Agent，Isabella Rodriguez，被植入目標：「想在 2 月 14 日下午 5 點於 Hobbs Cafe 舉辦情人節派對。」其他 24 個 Agent 沒有收到這個種子。在模擬的幾天中：

1. Isabella 的規劃包含邀請他人。
2. 每則邀請都會成為鄰居記憶流中的一條觀察。
3. 鄰居的反思會生成信念：「Isabella 正在辦派對。」
4. 鄰居的規劃加入了「2 月 14 日參加派對」。
5. 鄰居之間會互相轉告。邀請在沒有中央協調的情況下擴散開來。
6. 2 月 14 日下午 5 點，多位 Agent 陸續聚集到 Hobbs Cafe。

這就是技術意義上的「湧現（Emergence）」：系統層級的行為（一場派對）由局部互動（雙邊邀請 + 個別規劃）產生，沒有中央的編排者（orchestrator）。

### 文獻記錄的失效模式

Park 等人明確記錄了以下問題：

- **空間常規錯誤。** Agent 會走進已經打烊的店。多個 Agent 會嘗試使用同一間單人洗手間。Agent 會在不該用餐的房間吃東西。模型無法只從環境推斷社會與物理規範。
- **記憶溢出。** 長時間的模擬會讓記憶檢索成本增加。實用的做法：定期壓縮記憶（摘要並修剪），並讓低重要性條目衰減。
- **反思幻覺（Reflection hallucination）。** 反思可能編造記憶流中不存在的關係。緩解方式：在反思 prompt 中包含來源記憶 ID，並在檢索時驗證。

這些問題都與正式環境直接相關：2026 年的任何 Agent 模擬都會繼承它們。

### 三元件的實作規則

1. **記憶僅能附加。** 不得修改既有記憶；修正以新條目表示。
2. **重要性評分很便宜。** 寫入時呼叫 LLM 給出 1–10 的評分，並快取該分數。
3. **檢索採排序，而非過濾。** 依綜合分數取 Top-k；不要用硬性過濾器（它會丟失上下文）。
4. **反思定期執行。** 未處理記憶的重要性總和超過門檻（例如 150）時觸發。
5. **規劃可修訂。** 當新觀察與規劃衝突時，只重新生成受影響的片段，而非整個規劃。

### 超越 Smallville 的生成式 Agent

2024 至 2026 年的後續文獻延伸了這個架構：

- **用於政策與市場研究的多 Agent 社會模擬。** 一群類 Smallville 的 Agent 模擬使用者對功能的反應。比 A/B 測試快；準確性仍有爭議。
- **遊戲 NPC AI。** 使用 Smallville 式 Agent 的 RPG 會產生湧現式故事線，而非預先寫好的任務。
- **生成式 Agent 的評測基準。** 指標不是任務準確率，而是長時間執行中行為的擬真度（Believability）與連貫性。

Smallville 架構是參考基準。延伸版本會替換元件（例如用向量資料庫儲存記憶、檢索增強反思、神經符號規劃），但保留三部分結構。

### 對多 Agent 工程的意義

Smallville 證明：只要元件正確，多 Agent 湧現的成本可以很低。該架構如今已能在開源模型上復現（較小的 LLM 會平緩而非急劇地失去擬真度）。需要**湧現式社會行為**的正式環境系統，都會採用這種形狀。需要**嚴密任務執行**的系統，則使用本階段前面的監督者、角色與原語模式。

## Build It｜動手實作

`code/main.py` 以標準函式庫實作三個元件，並以腳本化策略（policy）模擬 Agent（沒有真正的 LLM）。示範以小規模重現情人節派對的湧現：

- `MemoryStream`——僅能附加的記憶流，依新近度、重要性與相關性檢索。
- `reflect(stream)`——針對近期高重要性記憶進行腳本化反思提煉。
- `plan(agent_state)`——依據當前信念生成日層級與小時層級的規劃。
- 情境：5 個 Agent。Agent 1 一開始的目標是「下午 5 點辦派對」。隨著模擬時間步推進，邀請擴散，Agent 逐漸聚集。

執行指令：

```
python3 code/main.py
```

預期輸出：逐時間步的追蹤紀錄。到最後一個時間步，5 位 Agent 中至少 3 位的規劃包含派對，並在派對地點聚集。單一種子在沒有編排者的情況下產生了協調的聚集。

## Use It｜實際應用

`outputs/skill-simulation-designer.md` 為生成式 Agent 模擬設計方案：Agent 數量、記憶結構描述（schema）、反思節奏、規劃期程，以及評估指標。

## Ship It｜交付成果

正式環境模擬的規則：

- **記憶就是資料庫。** 規模化時應選用真正的儲存方案（向量資料庫、Postgres）。純記憶體標準函式庫只適合原型。
- **記錄檢索軌跡。** 對每個行動，記錄驅動它的 top-k 記憶。這是除錯的依據。
- **為每個 Agent 規劃 token 預算。** 每個 Agent 每時間步的檢索、反思與規劃各需 O(k) 次 LLM 呼叫；N × T × 每步呼叫數可能遠超預算。
- **定期壓縮記憶。** 摘要並修剪低重要性條目。保留策略是設計決策，不是細節。
- **明確偵測空間與社會常規違規。** 此架構不會自己學會這些規則。

## Exercises｜練習

1. 執行 `code/main.py`，確認有 3 位以上的 Agent 抵達派對。把 Agent 增加到 10 個，湧現還會發生嗎？
2. 移除反思步驟。行為看起來如何？與 Park 2023 的消融結果對照。
3. 加入一個互相競爭的種子目標（例如「Klaus 想在下午 5 點發表研究演講」）。Agent 會分裂，還是其中一個目標佔主導？什麼因素決定結果？
4. 加入空間限制：Hobbs 咖啡廳最多容納 4 位 Agent。模擬能否妥善處理超載，還是會出現「多人擠單人廁所」的失效？
5. 閱讀 Park 等人論文（arXiv:2304.03442）第 6 節（湧現行為實驗）。找出一個你的微型版本無法重現的行為，並說明需要強化架構的哪個元件。

## Key Terms｜關鍵術語

| 術語 | 常見說法 | 實際意義 |
|------|----------|----------|
| 記憶流 | Agent 的日記 | 僅能附加的日誌，記錄觀察、行動、反思與規劃。 |
| 新鮮度 | 這段記憶有多新 | 依時間年齡計算的指數衰減分數。 |
| 重要性 | Agent 有多在意 | 寫入時由 Agent 自評 1–10，並快取。 |
| 相關性 | 與目前查詢有多相關 | 餘弦相似度（基於 embedding）。 |
| 反思 | 高階信念 | 從近期記憶生成的綜合結論，再以新記憶寫回。 |
| 規劃 | 日／小時／行動的分解 | 自頂向下的規劃樹。觀察與規劃衝突時可修訂。 |
| Smallville | Park 2023 的沙盒 | 產生情人節派對湧現的 25 Agent 模擬。 |
| 擬真度 | 品質指標 | 人類評審對行為是否像可信 Agent 的評分。 |
